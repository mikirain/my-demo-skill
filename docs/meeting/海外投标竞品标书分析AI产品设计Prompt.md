### 任务七：Agent 与人工如何协作

重点设计一个可落地的人机协作机制，而不只是简单地说“AI 提效、人类审核”。

请围绕以下过程展开：

1. 用户创建项目并上传资料。
2. Agent 自动识别文件类型、章节结构和资料关系。
3. Agent 识别关键技术参数并生成证据索引。
4. 系统通过规则引擎校验单位、范围、字段完整性和条件一致性。
5. Agent 对照已授权的我方产品资料与竞品数据。
6. 系统识别低置信度、参数冲突、证据缺失和高风险项。
7. 技术工程师处理异常并确认关键参数。
8. Agent 基于已确认数据生成差距分析和初步建议。
9. 产品或投标负责人审核高风险结论和应答策略。
10. 系统输出报告，保留完整的证据链、修改记录和审批记录。

请明确每一步中 AI 与人的职责边界，并给出触发人工审核的具体规则，例如：

- 关键技术参数置信度低于预设阈值。
- 原文存在多处冲突。
- 单位或测试条件无法统一。
- 招标强制条款可能不满足。
- 关键结论缺少可验证证据。
- 涉及产品性能承诺、质保条款、商务报价或正式投标应答。

同时说明审核结果如何反馈到系统：哪些信息可进入经过审批的项目知识库，哪些信息只在当前项目内有效，如何避免错误答案被反复复用。

请设计至少 3 个典型异常场景，并给出 AI 处理、人工介入、最终输出的完整闭环。

6. 如何识别低置信度结果并请求人工审核。

### 任务十：效果评估与风险治理

设计一套可量化、可验收的评估体系，至少包含：

1. 参数抽取准确率与召回率。
2. 原文证据定位准确率。
3. 单位换算和标准化正确率。
4. 关键条款漏检率。
5. 竞品对比结果正确率。
6. 人工复核率与人工修改率。
7. 单份文档及完整项目的处理时间。
8. 报告生成后被专业人员接受或修改的比例。
9. 敏感数据访问与导出审计情况。

请说明每个指标的定义、计算方式、测试数据来源和验收方法。没有实际测试数据时，只能提出目标值建议，并标注为待验证的验收目标，不能伪称已经取得成效。

同时分析：

- 大模型幻觉与无来源结论。
- OCR 和表格解析错误。
- 竞品信息过时或来源不可靠。
- 测试条件不同导致的错误比较。
- 多语言及专业术语问题。
- 企业敏感信息泄露。
- Prompt Injection 与文档内恶意指令。
- Agent 工具权限过大或越权操作。
- 错误结论进入知识库并被重复传播。
- 模型调用成本、响应延迟及供应商依赖。

请给出相应的防护、监控和回滚机制。

## 六、研究与输出规范

1. 先调研，再分析，最后设计产品。不得跳过企业和行业调研，直接输出通用 AI 产品方案。
2. 对关键事实进行联网检索并引用原始来源，提供可访问的链接和资料日期。
3. 优先采用官方资料、权威行业报告和公开招标文件；对于二手信息，明确说明其来源属性。
4. 严格区分事实、行业惯例、合理推断、设计建议和待验证假设。
5. 不得编造企业内部流程、真实客户项目、竞品参数、访谈结果或实施效果。
6. 不要把“接入大模型”当成完整解决方案，必须说明数据流、工具调用、业务规则、审核节点和异常处理。
7. 不要把所有问题都交给 Agent。对于可确定计算的任务，优先使用可测试、可审计的规则和程序。
8. 产品设计应体现企业级要求，包括权限、数据隔离、版本控制、证据溯源、审计日志及人工审批。
9. 输出内容应具体、务实、可实施，尽量使用表格、流程图、示例和明确的设计决策。
10. 不要仅罗列功能。每项核心功能都要说明解决的具体问题、用户如何操作、系统如何处理以及如何判断结果正确。
11. 不要虚构量化收益。可以提出待验证的目标值，并说明如何通过试点验证。
12. 使用中文撰写，专业术语首次出现时给出中文解释；英文缩写应在首次出现时说明。
13. 如果报告过长，可以分章节输出，但应先给出完整目录和核心结论，再逐章展开。
14. 遇到公开信息不足的部分，明确列出假设和待核实问题，不要自行补齐为事实。
