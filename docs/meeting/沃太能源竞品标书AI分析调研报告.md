## PART 01 · 为什么选择课题 1

**课题 1 · 海外投标中的竞品标书分析**：沃泰在海外大储项目主要通过招投标获得订单，一个项目往往要与多家国际对手同台竞争。投标团队需要逐页阅读对手的标书与技术参数，手动整理成对比表，再找出我方差距。一个项目资料动辄数百页，靠人肉翻文档既慢又容易漏项，标书分析的质量直接影响报价与应答策略。

**选择理由（三个维度）：**

1. **战略权重高**：沃太正从「户储为主」向「户储 + 工商储 + 大储」转型（2023 年已成为中国工商储出货 Top 8，2025 年底连获德国、捷克大储订单），大储订单基本靠招投标获取，投标能力 = 订单能力。
2. **痛点典型且量级大**：数百页、多语种、技术/商务/法务混合的文档分析，是典型的「长文档理解 + 结构化抽取 + 对比推理」问题，恰好是大模型相对人工的优势区。
3. **AI 落地路径清晰**：文档解析、信息抽取、RAG 对比、策略生成均有成熟技术组件；与课题 5（投标文件编制）构成「标前分析 → 标书生成」的完整闭环，且可复用到课题 2（合同审查）、课题 15（政策情报）等文档类场景，平台复用价值高。

## PART 05 · 业务流程与痛点：海外大储招投标是怎么打的

### 5.1 业主侧采购流程（沃太作为投标方全程参与）

1. **资格预审 PQ**：财务能力、项目业绩、HSE 记录、关键人员资质、制造/分包资源
2. **RFQ/RFP 发布**：技术规格书、范围边界、接口条件、合同条件草案、评标规则
3. **答疑与澄清**：统一答疑窗口、现场踏勘、Data Room；要求提交偏差表
4. **投标**：技术方案 + 偏离表应答 + 报价单，数百页量级
5. **评标**：技术合规先行，再商务评审与澄清，最后 BAFO 最终报价
6. **授标与签约**：合同一致性审查（投标承诺、澄清纪要、偏差关闭记录与合同一致）

### 5.2 投标团队内部的「竞品分析」子流程与痛点

**现状流程（人工）：**

1. 获取竞对公开标书/技术应答/中标公示（多语种：英德荷西意等）；
2. 工程师逐页阅读，手动摘录技术参数（可用容量、RTE 效率及测量边界、循环寿命与衰减、温控、消防与安全认证、交期、质保）；
3. 用 Excel 手工整理「竞对 × 我方 × 招标要求」对比表；
4. 凭经验判断对手策略（低价抢标？技术承诺激进？），形成应答策略；
5. 将结论同步给报价、法务与销售管理层。

**核心痛点：**

- **慢**：一个项目数百页 × 多家竞对，分析周期常以「天—周」计，压缩了策略打磨时间；
- **漏**：效率数据若不核对测量边界（DC 块效率 / PCS 效率 / AC-AC 全系统效率）就会误判，漏掉一个偏离项可能在评标中被反超；
- **口径不一**：不同工程师摘录口径不同，跨项目、跨竞对不可比，难以沉淀；
- **情报孤岛**：历史投标的竞对资料散落在个人电脑与邮件里，复用率低，人员流动即知识流失；
- **多语种门槛**：德/荷/西语技术文档依赖个别语言能力员工；
- **商业敏感**：竞对标书是高度敏感信息，不能上公有云通用 AI 工具（合规与泄密风险）。

## PART 06 · 行业 AI 实践：招投标 AI 已经走到哪一步

| 实践方 / 产品                                | 已验证的能力与效果                                                                                                                                                                                |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **中国移动「中移灵采」**（央企级样板，2026） | 「Agent + Skill」智能体架构，接入多模型；招标文件解析、标书智能撰写、知识库管理，标书编制审核周期由数天缩短至 30 分钟内，资料检索效率提升 90%；合规自动校验 40+ 核查项，10 分钟完成、准确率超 90% |
| **钛投标**（垂直大模型）                     | 招标文件智能解析、标书自动撰写、资质合规自检、废标风险排查、历史标书对比；服务 17 万家企业，数日级工作压缩至数十分钟                                                                              |
| **智标领航 / 投标三剑客**（SaaS）            | 招标文件 3 分钟划重点、原文定位一键跳转核对；偏离表智能生成与参数校对；竞对分析、模拟评标、废标项/串标项检查、检查报告与优化建议                                                                  |

**可迁移的通用结论：**

1. 文档解析 + 原文溯源是信任基础；
2. 结构化「参数矩阵 + 偏离表」是核心交付物；
3. 风险检查（废标项类比于此处的应答缺口）ROI 最直接；
4. 知识库沉淀决定长期复利；
5. 私有化部署是能源/央国企场景的前提。

> 与通用 SaaS 的关键差异：沃太需要的是「私有化 + 竞品视角」——分析的输入是**对手的标书**而非招标文件，输出是「差距与策略」而非「合规标书」。市面产品没有直接可套用的，需要自建场景化方案，但技术组件与交互范式高度可借鉴。

## PART 07 · 产品设计：竞品标书智能分析工作台

### 7.1 用户是谁

| 角色                                    | 典型场景                                                | 最关心的产出                         |
| --------------------------------------- | ------------------------------------------------------- | ------------------------------------ |
| **投标经理 / 大储方案工程师**（主用户） | 投标窗口期内同时跟进 2–3 个项目，负责竞品分析与技术应答 | 参数对比矩阵、差距清单、偏离表初稿   |
| **报价与商务**                          | 需要知道对手报价结构与商务条款（账期/质保/履约保函）    | 商务条款对比、报价区间建议           |
| **区域销售总监 / 管理层**               | 投标 Go/No-Go 决策、定价与让利审批                      | 一页式策略简报（胜负手、风险、建议） |
| **法务 / 合规**（次用户）               | 竞对承诺条款的风险核查、我方应答合规                    | 红旗条款清单                         |

### 7.2 解决什么问题（价值主张）

- **天 → 小时**：数百页 × 多竞对标书分析，从 3–5 天压缩到数小时出初稿
- **漏项 → 溯源**：每一条抽取均带原文页码引用，效率口径、质保边界不再误判
- **个人经验 → 组织资产**：竞品情报沉淀为企业级知识库，跨项目复用、随项目增值

### 7.3 核心功能（六个模块）

1. **多源文档摄取与解析**：PDF/扫描件/Excel/图纸 OCR；英德荷西意多语种自动识别与翻译；按章节（技术规格/商务条款/偏离表/资质证明）智能切分。
2. **参数矩阵自动抽取**：按储能行业参数字典抽取：可用容量与放电时长、RTE 及测量边界、循环寿命与衰减曲线假设、温控方式与降额、安全认证（NFPA/IEC/并网标准）、交期、质保年限、业绩案例。低置信度字段标注「待人工确认」。
3. **三方对比与差距分析**：「招标要求 × 我方产品库 × 各竞对」三向对齐；逐项判定 符合 / 偏离 / 未应答；按评标权重加权，输出优劣势热力图与「胜负手」摘要。
4. **竞品情报库（长期复利）**：历次项目竞对资料、中标结果、公开产品手册统一入库；支持语义检索；随项目数增长形成护城河。
5. **策略与应答建议**：基于差距生成应答策略：技术差异化卖点、可承诺边界建议、商务条款对齐建议、报价区间参考（联动内部成本模型）；一键生成偏离表初稿，衔接课题 5 的标书编制。
6. **风险与红旗识别**：对手异常低价/激进承诺识别、我方应答缺口与废标风险预警、条款冲突检查；输出风险清单供评审会使用。

### 7.4 交互流程（一个投标项目的完整使用旅程）

1. **建项目/传文档**：招标文件 + 竞对公开资料拖拽上传；自动关联竞品库已有档案
2. **AI 解析抽取**：分钟级完成全文档解析，生成参数矩阵草稿，全部字段带原文定位
3. **人工校对确认**：工程师抽检低置信度字段、修正口径（如效率测量边界）；修正回流知识库
4. **对比与策略生成**：一键生成差距热力图、胜负手简报、应答策略与偏离表初稿
5. **评审与人工定案**：投标例会基于简报决策；管理层批注定价与承诺边界
6. **归档与复盘**：中标/丢标结果回写，竞对策略复盘沉淀，反哺下一次投标

全程 Web 工作台 + IM 通知（进度、待办、红旗告警），支持多项目并行看板。

## PART 08 · AI 如何落地：Agent 架构与人机协作机制

### 8.1 多 Agent 协作架构

采用「主 Agent 编排 + 专业子 Agent」（对标中移灵采的 Agent+Skill 模式），底层为：文档解析模型（多语种 OCR + 版面理解）、行业 LLM（通用大模型 + 储能参数字典/术语库微调）、向量知识库（竞品情报 + 我方产品库 + 国别政策）、内部成本与产品数据库（私有化部署，数据不出内网）。

| Agent                  | 职责                                                                          | 关键设计                                             |
| ---------------------- | ----------------------------------------------------------------------------- | ---------------------------------------------------- |
| **编排 Agent**（主控） | 理解任务（「分析这个项目的 3 家竞对」），拆解调度子 Agent，汇总产出工作台结果 | 任务状态机管理；失败重试与降级（解析失败转人工通道） |
| **解析 Agent**         | 多格式/多语种文档切分、OCR、表格重建、章节分类                                | 表格数字优先用规则+OCR 校验，而非纯生成              |
| **抽取 Agent**         | 按参数字典抽取结构化字段，附原文页码引用                                      | 输出置信度；低于阈值自动转入人工待办                 |
| **对比分析 Agent**     | 三向对齐、加权评分、差距归因（是产品差距还是应答策略差距）                    | 判定规则显式化（如效率必须同边界比较），可由专家配置 |
| **策略 Agent**         | 生成应答策略、偏离表初稿、简报草稿                                            | 只引用已确认的事实字段，杜绝「编造参数」             |
| **质检 Agent**         | 交叉校验抽取结果与原文一致性、策略与事实一致性                                | 引用溯源抽检 + 数值一致性比对，把幻觉拦截在交付前    |

### 8.2 Agent 与人协作的机制（Human-in-the-Loop 设计）

| 机制                              | 具体做法                                                                                                                                                                             |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **三道人工关卡**                  | ① 解析后：人工校对低置信度字段（系统只把「拿不准的 20%」推给人）；② 策略发布前：投标经理审核确认，AI 产出始终是「草稿/建议」而非定论；③ 定价与对外承诺：永远由人决策，Agent 无权触发 |
| **置信度路由**                    | 每个抽取字段带置信度：高 → 直接入矩阵（可抽检）；中 → 高亮提示复核；低 → 强制人工录入。随人工修正样本回流，人工作量逐月下降                                                          |
| **提案—确认（Proposal–Approve）** | Agent 所有动作可逆、留痕：修改对比表=建议态，人点击采纳才生效；差异用 diff 视图呈现，人只审「AI 改了什么」                                                                           |
| **证据链与可解释**                | 矩阵中每个数字可一键跳转原文页码；策略结论附「依据字段清单」，评审会上可当场对质——这是赢得工程师信任的关键                                                                           |
| **人教机学（反馈回流）**          | 人工修正自动写入金标准样本集与知识库；评标结果（中标/丢标及原因）回写，持续校准对比权重与策略建议                                                                                    |
| **安全与合规边界**                | 私有化/专有云部署；竞对标书分级加密、水印与权限（按项目组最小可见）；审计日志全留痕；模型调用不出内网（可用开源模型本地推理）                                                        |

> **协作哲学**：Agent 负责「读得全、比得准、想得快」，人负责「判得对、敢拍板、担责任」。AI 不替代投标经理的判断，而是把每个人从数百页文档中解放出来，把组织从「知识随人走」变成「情报随项目沉淀」。

### 8.3 预期收益（可作为试点 KPI）

- 单项目竞品分析初稿时间 **≤ 4 小时**（现状 3–5 天）
- 关键参数抽取召回率 **95%+**（以人工金标准评估）
- 结论可溯源率 **100%**（每个数字可定位原文）
- **中标率提升**：应答策略质量提升 + 复用历史竞品情报

### 主要风险与对策

- **数据敏感与泄密风险**：私有化部署 + 权限分级 + 审计，竞对标书严禁流向公有模型；
- **抽取错误传导**：引用溯源 + 质检 Agent + 人工关卡三重拦截，宁可标注「未知」不猜；
- **用户信任建立慢**：从「省时间的工具」切入（自动对比表），先赢日常使用，再扩展到策略建议等高价值高信任场景；
- **竞对资料获取不稳定**：以公开渠道（中标公示、产品手册、官网参数）为主，项目中标后复盘补充，情报库渐进积累。
