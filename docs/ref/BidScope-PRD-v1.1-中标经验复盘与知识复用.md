## 1. 一句话诊断

v1.0 是一个**投标前（ex-ante）的竞品分析工作台**：输入对手标书，输出差距与应答建议，评标结束即归档。
`修改优化建议.md` 指出真正长期价值在**投标后（ex-post）**：从中标标书里提炼「可复用、有证据、适用于当前项目」的经验。

**当前系统缺失的三件事**

1. **没有中标后的复盘对象**：`BidResult` 在 v1.0 只是枚举字段，没有承载「为什么赢」的结构化事实；
2. **没有证据强度概念**：所有结论一律平权，无法区分「评分表写明我们得分高」与「我觉得是这个原因」；
3. **没有复用路径**：情报库只存竞对参数，不存「什么条件下可借鉴」，因此不能用于新项目决策。

| 8 | 商务条款与合同风险 | 有红旗条款清单（研判页），无「中标后是否留下难兑现义务」 | 新增合同风险复盘 + 履约验证联动（承诺 vs 实际） | 中标复盘页 › 合同与履约 |

## 3. 证据分级（本次最重要的机制）

> 中标 ≠ 标书里每一项设计都导致中标。必须把「已证实」与「以为」分开。

| 级别 | 定义 | 典型证据 | 界面表现 | 可用于决策 |
| --- | --- | --- | --- | --- |
| **A** | 有直接证据 | 正式评分表得分、客户澄清邮件明确认可、评标反馈点名优势 | 实线徽标「A 已证实」 | 可直接写入策略建议 |
| **B** | 多项材料共同支持 | 投标文件 + 澄清记录 + 合同谈判记录共同指向，但无评标直接证据 | 双线徽标「B 多材料」 | 可作为参照，需注明限制 |
| **C** | 待验证假设 | 只有结果，无因果证据 | 虚线徽标「C 待验证」 | 只能标注为假设，禁止作为结论 |

**硬规则（新增）**

- BR-11：经验条目必须带 `evidenceLevel` 与 `evidenceSources`，无来源不得入库；
- BR-12：C 级经验在相似项目匹配结果中只能出现在「待验证假设」区，不得进入「可借鉴」区；
- BR-13：无正式评分表的项目，`hasScoreSheet=false`，其全部经验最高只能评 B 级；
- BR-14：履约验证为 `missed` 时，对应经验自动降级并提示复核；
- BR-15：引用经验到新项目必须留痕（谁、何时、引用了哪条、用于哪份文件）。

## 4. 四类经验库（数据资产）

| 经验库 | 内容 | 解决什么问题 | 对应 `Experience.category` |
| --- | --- | --- | --- |
| 竞品策略库 | 厂商方案特点、产品差异、服务优势、证据来源 | 下次遇到相似竞品，快速判断竞争重点 | `competitor` |
| 技术响应与偏差库 | 招标条款、产品证据、偏差原因、澄清结果 | 减少重复分析与响应遗漏 | `deviation` |
| 商务与交付案例库 | 报价结构、合同风险、交期、本地化经验 | 降低不合理承诺与履约风险 | `commercial` |
| 中标项目知识库 | 项目背景、关键需求、最终方案、中标原因、履约结果 | 复用成功经验，支撑投标决策 | `awarded` |

**每条经验必须保留的 12 个字段**（建议原文要求）
国家/地区、项目规模、客户类型、投标模式、产品型号、招标要求、采取的策略、最终结果、证据来源、复盘人、复核日期、适用范围 → 全部落入 `Experience` 类型，缺任一必填字段不允许提交入库。

## 5. 相似项目匹配（让经验「适配」而非「照搬」）

匹配不是相似度排序就完事，必须同时回答两个问题：**哪些可借鉴**、**哪些条件不同**。

```
score = 国家匹配(30) + 规模相近(25) + 技术路线(15) + 客户类型(15) + 合同模式(15)
```

输出结构：

| 输出 | 说明 |
| --- | --- |
| 匹配度 | 0–100，仅作排序依据，界面标注「匹配度不代表经验可直接套用」 |
| 可借鉴点 | 命中的经验条目（按证据等级分区：A/B 可借鉴，C 单列为待验证假设） |
| 差异条件 | 明确列出不匹配的维度（如国别并网规范不同、规模差 4 倍、客户类型不同） |
| 适用边界 | 引用自经验的 `scope` 字段，说明「在什么条件下成立」 |

## 6. Agent 分工（承接建议第四节）

| Agent | 职责 | 与 v1.0 的关系 | 人机边界 |
| --- | --- | --- | --- |
| 竞品标书分析 Agent | 抽参数、生成有出处对比矩阵、标注缺失与不可比 | v1.0 已有（解析/抽取/对比/研判） | 不变 |
| **中标经验复盘 Agent** | 对照招标要求、最终投标版本、评标反馈、澄清记录、履约结果，产出「已证实优势 / 可能原因 / 待验证假设」三栏 | 新增 | 证据等级由人确认，AI 只能建议 |
| **相似项目匹配 Agent** | 按国家/规模/路线/客户/合同模式检索历史项目，解释可借鉴点与差异条件 | 新增 | 引用需人确认并留痕 |
| **风险与偏差 Agent** | 检查当前项目是否重复历史证书缺失、口径不一致、交付风险、非标条款 | 新增（复用经验库 + 偏差库） | 命中项交技术/商务/法务确认 |
| 人工协同与审批 | 技术确事实、商务法务确条款、供应链确交付、投标经理汇总决策 | v1.0 审核体系扩展 | 最终决策永远由人做 |

## 7. 新增数据模型

```ts
export type EvidenceLevel = 'A' | 'B' | 'C';
export type ExperienceCategory = 'competitor' | 'deviation' | 'commercial' | 'awarded';

export interface AwardedProject {
  id: string; name: string; country: Country; mw: number; mwh: number;
  customerType: string; bidMode: string; contractMode: string;
  productModel: string; awardedYear: number; competitorIds: string[];
  hasScoreSheet: boolean; snapshotAt: string;
  factors: WinFactor[];
}

export interface WinFactor {
  id: string; title: string; category: 'price'|'tco'|'safety'|'efficiency'|'delivery'|'local'|'reference'|'compliance';
  level: EvidenceLevel; customerNeed: string; ourResponse: string; competitorGap: string;
  evidence: string[]; confirmedBy?: string;
}

export interface Experience {
  id: string; category: ExperienceCategory; title: string; summary: string;
  projectId: string; country: Country; scaleBand: string; customerType: string;
  bidMode: string; productModel: string; requirement: string; strategy: string;
  result: string; evidenceLevel: EvidenceLevel; evidenceSources: string[];
  reviewer: string; reviewedAt: string; scope: string;
  state: 'draft' | 'verified' | 'deprecated';
}

export interface FulfilmentRecord {
  id: string; projectId: string; commitment: string; target: string; actual: string;
  variance: string; status: 'met' | 'partial' | 'missed' | 'pending';
  note: string; verifiedAt: string;
}

export interface MatchResult {
  project: AwardedProject; score: number;
  matched: string[]; differences: string[];
  usableExperiences: Experience[]; hypotheses: Experience[];
}
```

- [ ] 任一中标项目可看到三栏证据，且 A/B/C 徽标形状不同（不只靠颜色）；

## 12. v1.1.1 增补 · 证据等级变更审批

> 原 v1.1 只允许「履约未达标」引发降级，等级本身由复盘人线下确认。本节把等级变更做成**可申请、可审批、可追溯**的闭环。

### 12.1 规则

| 编号 | 规则 | 说明 |
| --- | --- | --- |
| LR-01 | 升级必须新增证据 | 目标等级高于当前等级时，`evidenceSources` 至少 1 条 |
| LR-02 | 升到 A 级必须有直接证据 | 且来源项目须有正式评分表，否则按 BR-13 拒绝 |
| LR-03 | 变更必填理由 | ≥ 6 个字，写入审计 |
| LR-04 | 双人规则 | 不可审批本人发起的变更（BR-08） |
| LR-05 | 单条经验同时只允许一个待审变更 | 避免等级来回跳 |
| LR-06 | 审批通过后追加证据来源并置为「已核验」 | 去重合并，已停用条目不改状态 |
| LR-07 | 降级可不附证据 | 但必须写明原因，且同样走审批（保守优先） |
| LR-08 | 全部变更进入变更历史 | 含发起人、时间、理由、证据、审批人、审批意见 |

### 12.2 状态流

```
无申请 → 待审批 → (已通过：等级生效 + 证据并入) 
                └→ (已驳回：等级不变，原因留痕)
```

### 12.3 界面落点

- 经验库详情抽屉新增「证据等级变更」区块：当前等级规则说明、申请按钮、待审批卡片（含证据清单与理由）、变更历史时间线；
- 待审批卡片内「通过」按钮在发起人＝当前用户时禁用，并给出 BR-08 说明；
- 经验列表在状态列追加「等级待审」徽标，便于批量巡查；
- 申请弹窗：目标等级下拉、新增证据（多行）、变更理由，校验失败就地报错。

### 12.4 验收标准（增补）

- [ ] 升级未填证据时提交被拒绝，错误显示在弹窗内；
- [ ] 无评分表项目申请 A 级被拒绝，提示 BR-13；
- [ ] 本人发起的变更「通过」按钮禁用并说明原因；
- [ ] 审批通过后等级立即生效、证据来源合并、历史出现「已通过」；
- [ ] 驳回需填理由，经验等级保持不变且历史出现「已驳回」；
- [ ] 每次申请/通过/驳回均产生审计事件。
