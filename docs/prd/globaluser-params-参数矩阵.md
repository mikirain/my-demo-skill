## 1. 页面目标

参数矩阵是 F3 抽取结果与 F4 标准化结果的**唯一人工落点**。系统抽出的 40 条实例（项目 p-01）如果没有人逐条判断「这个数字能不能用」，下游的对比、研判、报告全部建立在不稳固的数值上。本页要解决的问题有三个：

1. **让不可信可见**：每条实例必须一眼看出置信度档位、是否有证据、是否存在多值冲突，工程师不必逐条点开猜；
2. **让不可比有依据**：原始值与标准化值并列呈现，测试条件、系统层级同屏可得，条件缺失不隐藏、不补零；
3. **让修改可追责**：任何人工修正必须写理由并留痕，修正后回流知识库与金标准集（BR-09）。

**成功标准**（可度量，作为验收口径）

| 编号 | 标准 | 目标 |
| --- | --- | --- |
| S-01 | p-01 全部待复核实例（12 条待确认 + 2 条强制人工 + 2 条冲突）单轮复核耗时 | ≤ 40 分钟 |
| S-02 | 证据可达率 | 抽检 20 行，证据入口 100% 可定位到文件 + 页码 + 片段 |
| S-03 | 修正留痕完整率 | 修正记录 100% 含原值、新值、人、时间、理由、版本 |
| S-04 | 缺失值合规率 | 未披露行 100% 显示 `—`，无 0 填充（BR-02） |
| S-05 | 高置信度误拦率 | 0.85 以上实例进入强制复核队列的比例 = 0 |

### 4.2 视觉层级

- **第一层**：页头标题与 5 个置信度计数（谁最不可信，一眼看到数字）；
- **第二层**：表格「标准化值」与「状态」两列，等宽数字右对齐，是复核动作的判断依据；「原始值」用 `--ink-2` 弱化，避免与标准化值抢注意力；
- **第三层**：条件、层级、证据、置信度数值，用 12px 小字与灰边 chip，只看不抢；
- **证据缺失行**：整行左侧 2px `--line-strong` 竖条 + 数值 `--ink-3`，不做高亮底色（BR-01 要求降权而非警示）；
- **冲突行**：左侧 2px `--danger` 竖条 + 双线边框 chip，是页面上唯一允许出现红色竖条的行类型；
- **信息密度**：标准密度每屏可见 14 行（含表头与工具条）；紧凑密度每屏 18 行，隐藏原始值第二行与证据片段。

### 5.3 置信度 chip 与计数口径

| chip | 判定条件 | 颜色 / 图标 / 形状 | 主 chip 计数（p-01） |
| --- | --- | --- | --- |
| 待确认 | `0.60 ≤ confidence < 0.85` 且 `status = pending` | `--warn` / clock / 实线单边框 | 12 |
| 强制人工 | `confidence < 0.60`（BR-10） | `--danger` / alert / 实线 + 左侧 3px 竖条 | 2 |
| 冲突 | `status = conflict` 或保留 ≥2 个取值（BR-07） | `--danger` / alert / **双线边框** | 2 |
| 已修正 | `status = corrected`，有 `correctedBy` / `correctedAt` / `reason` | `--accent` / edit / 实线 | 0 |
| 已确认 | `status = confirmed`，或 `confidence ≥ 0.85` 的免检行 | `--ok` / check / 实线 | 24 |
| 无引用（叠加） | `evidence` 为空（BR-01） | `--ink-3` / minus / **虚线边框** | 2（不参与主计数） |

**计数规则**：每条实例只归属一个**主 chip**，优先级 冲突 > 强制人工 > 已修正 > 待确认 > 已确认，因此主 chip 合计恒等于 40；「无引用」是叠加标记，在行内作为次 chip 出现（最多显示 2 个，多出显示 `+1`），计数条上单独列出，不与主计数相加。示例：pv-020 主 chip 为「强制人工」，次 chip 为「无引用」。

**免检行的表达**：`confidence ≥ 0.85` 但 `status` 仍为 `pending` 的 4 条（pv-009、pv-014、pv-017、pv-037）按 BR-10 进入抽检而非逐条复核，状态列显示「待复核 · 免检」灰字，主 chip 计入「已确认」，**不占用「待确认」计数**。

## 6. 主次行动

### 7.3 行内修正（数值 + 理由必填）

**场景叙述二（投标经理王琛在评审会前 10 分钟）**
