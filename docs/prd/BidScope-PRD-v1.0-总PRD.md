## 1. 产品定位

### 1.1 一句话

> **BidScope 把「读对手的标书、对齐口径、比出差距」这件事，从数天的人工翻页，变成数小时内可溯源的证据矩阵；它不替人做决定，只把人从翻文档里解放出来去做判断。**

### 1.2 定位三角

| 维度 | 是 | 不是 |
| --- | --- | --- |
| 产品形态 | 投标团队内部的分析工作台（项目制、有审核流、有证据链） | 通用文档问答机器人、通用知识库 |
| 输入 | 对手的标书/手册/中标公示 + 招标要求 + 我方产品资料 | 只处理招标文件（那是投标编制系统的活） |
| 输出 | 差距清单、口径冲突、风险分级、待澄清问题、简报草稿 | 自动报价、自动承诺指标、自动 Go/No-Go |

### 1.3 与原 PRD 的差异（本次重写的判断）

| 变化 | 原 v0.2 | v1.0 | 理由 |
| --- | --- | --- | --- |
| 数据契约 | 分散在各功能章节 | 抽象为 **ParameterValue 五元组**（值/单位/条件/层级/证据） | 口径一致性问题的根因是「值脱离条件」，必须先在模型层解决 |
| 可比性 | 「不可直接比较」作为一种判定态 | 升级为**可计算属性** `comparable()`，由层级、单位、条件、边界四要素机械判定 | 让「不可比」有规则依据，不靠人拍脑袋 |
| 原则 | 分散的 BR 列表 | 提炼 4 条第一原则（证据优先、缺失不等于零、不可比不排名、决策留白） | 前端每个交互都可由原则推导，避免逐页设计走形 |
| 判定优先级 | 未定义 | 强制条款偏离 > 不可比 > 证据不足 > 偏离 | 评标现实里废标风险压倒一切，界面排序必须反映这一点 |
| Demo | 无 | 明确 12 路由、11 页面、Mock 规模与验收清单 | 任务要求可运行 Demo，必须先把范围钉死 |

### 1.4 产品边界（Demo 与产品同边界）

- 不做竞品资料的爬取与代理获取，仅处理用户合法上传的资料；
- 不替代标书编制系统，只输出偏离表初稿与差距清单；
- 不生成报价数字、质保承诺、技术指标承诺，一律留占位由人填写；
- 不覆盖户储/工商储的渠道零售场景。

## 2. 用户与任务

### 2.1 角色

| 角色 | 类型 | 核心 Job to be Done | 主要页面 |
| --- | --- | --- | --- |
| 技术投标工程师 | 主用户 | 在投标窗口内拿到「可信、可溯源、口径正确」的参数矩阵 | 资料、参数矩阵、对比分析 |
| 投标经理 | 主用户 | 判断赢面与风险，产出可评审的结论 | 工作台、研判、审核、报告 |
| 商务/报价 | 次用户 | 看清对手商务条款与差异卖点 | 对比分析（商务维度） |
| 产品经理 | 次用户 | 从跨项目差距中排产品改进优先级 | 对比分析、情报库 |
| 管理层 | 决策人 | 5 分钟读懂竞争态势 | 报告中心（一页简报） |
| 法务/合规 | 次用户 | 找出红旗条款与承诺风险 | 研判（风险清单） |
| 系统管理员 | 支撑 | 控权限、看审计、配字典与阈值 | 系统管理 |

### 2.2 三类任务的完成定义

| 任务 | 完成定义（Definition of Done） |
| --- | --- |
| 抽取与校验 | 全部字段状态非「抽取中」；低置信度字段 100% 有人决策；冲突项全部有结论或明确挂起 |
| 对比与研判 | 每个参与对比的竞对每个维度有判定；高风险结论已审核；不可比项有书面理由 |
| 出报告 | 报告基于已发布快照；每条结论可回链字段与原文；未审项为零才允许导出 |

## 3. 核心业务闭环

```mermaid
flowchart LR
  A["摄取<br/>文档+来源标注"] --> B["抽取<br/>五元组+证据+置信度"]
  B --> C["校验<br/>标准化+规则+冲突"]
  C --> D["对比<br/>三向对齐+可比性判定"]
  D --> E["研判<br/>三段式结论+风险分级"]
  E --> F["审核<br/>三类关卡+双人规则"]
  F --> G["输出<br/>报告快照+证据索引"]
  G --> H["复盘<br/>中标结果回写"]
  H -. 情报复用 .-> B
```

**五阶段门禁（Gate）**

| 阶段 | 产物 | 门禁条件（不满足则无法进入下一阶段） |
| --- | --- | --- |
| 摄取 | 结构化文档树 + 页码映射 | 招标文件已标注；每份文档有来源可靠性等级 |
| 抽取 | 参数草稿矩阵 | 每个字段带证据引用，否则记为抽取失败 |
| 校验 | 标准化矩阵 + 冲突清单 | 条件字段缺失的项不得标记为「可比」 |
| 对比 | 判定矩阵 | Mandatory 项全部有判定 |
| 研判 | 结论卡片 + 风险清单 | 已确认字段数达阈值；涉及承诺项为占位符 |

## 4. 领域模型

### 4.1 核心实体

| 实体 | 说明 | 关键字段 |
| --- | --- | --- |
| Project | 一次投标项目，数据隔离单元 | id, name, country, mw, mwh, deadline, stage, members |
| Document | 一份资料 | id, projectId, type, sourceReliability, pages, parseStatus, qualityScore, hash |
| PageAnchor | 原文定位 | documentId, page, section, bbox, snippet |
| ParameterDef | 参数字典项（全局） | key, label, unit, domain, level, requiresConditions[] |
| ParameterValue | **核心数据契约**：某来源某参数的实例 | defKey, sourceId, rawName, rawValue, value, unit, conditions, level, evidence, confidence, status, reviewer |
| Competitor | 竞对主体 | id, name, tier, region, models[] |
| Requirement | 招标要求行 | id, text, mandatory, targetValue, unit, conditions, weight |
| ComparisonRow | 一行对比结论 | defKey, requirementId, cells[], judgedStatus, judgeReason, priority |
| Insight | 研判结论 | id, type(fact/inference/suggestion), text, evidenceIds[], adoptState |
| RiskItem | 风险 | id, level(high/mid/low), kind, text, owner |
| ReviewTask | 审核待办 | id, kind, targetRef, assignee, due, state, diff |
| Report | 报告快照 | id, template, version, publishedAt, author, watermark |
| AuditEvent | 审计事件 | id, actor, action, target, at, ip, result |
| BidResult | 评标结果（复盘用） | projectId, result(win/lose), rank, feedback |

### 4.2 ParameterValue 五元组（系统基石）

> **任何参数不得以裸值存在。** 值必须与单位、测试条件、系统层级、证据绑定，否则不可进入对比。

```
ParameterValue = {
  value        // 数值或原文表述
  unit         // 单位，未标注时显式记录为「未标注」
  conditions   // { dod, temperature, boundary, sohEnd, loadRate, ... }
  level        // cell | module | rack | system | plant
  evidence     // { documentId, page, section, snippet, sourceReliability }
}
```

### 4.3 可比性判定（可计算）

```
comparable(a, b) =
     a.defKey == b.defKey
  && a.level   == b.level
  && a.unit    ~= b.unit          // 可通过确定性换算归一
  && conditionsAligned(a, b)      // 全部必需条件齐备且一致
```

任一条件不满足 → 状态 `incomparable`，界面必须输出**差异说明**而非排名。

### 4.4 判定状态（六态）

| 状态 | 含义 | 界面优先级 | 是否可排名 |
| --- | --- | --- | --- |
| `deviation` | 明确偏离（值不满足且条件一致） | 2 | 是 |
| `potentialDeviation` | 潜在偏离（接近阈值/条件不完全一致） | 3 | 是（带提示） |
| `compliant` | 满足 | 6 | 是 |
| `noResponse` | 未应答（有要求无内容） | 3 | 否 |
| `insufficientEvidence` | 证据不足 | 4 | 否 |
| `incomparable` | 无法直接比较 | 2 | **否** |
| `undisclosed` | 未披露（原文确实没有） | 5 | 否 |

> 排序规则：`mandatory 且非 compliant` 的项永远置顶（用 `riskFlag` 单独标记），其次按优先级列排序。

## 6. 关键业务规则

| 编号 | 规则 | 落地位置 |
| --- | --- | --- |
| BR-01 | **证据优先**：任何数值必须可跳转原文，无证据的字段界面降权显示并标「无引用」 | 参数矩阵、对比表、研判卡片 |
| BR-02 | **缺失不等于零**：未抽到/未披露 一律不带值，禁止 0 填充 | 抽取、对比 |
| BR-03 | **未披露不等于不具备**：状态用 `undisclosed`，不计入劣势统计 | 对比、研判 |
| BR-04 | **不可比不排名** | 对比页禁用总排名，只出分维度 |
| BR-05 | **强制条款置顶**：Mandatory 非 compliant 单项即入废标风险清单 | 对比、概览 |
| BR-06 | **决策留白**：报价、承诺、Go-No-Go 只输出占位与依据 | 研判、报告 |
| BR-07 | **冲突不消解**：原文多值全部保留，冲突需人工裁决并填理由 | 参数、审核 |
| BR-08 | **双人规则**：高风险项禁止编辑人自审 | 审核 |
| BR-09 | **修正可审计**：原值/新值/人/时间/理由/版本全留痕 | 全站 |
| BR-10 | **置信度路由**：≥0.85 免检抽检；0.60–0.85 提示复核；<0.60 强制人工 | 参数、审核 |

## 7. 非功能要求

| 类别 | 要求 |
| --- | --- |
| 技术栈 | Angular 最新稳定版，standalone component + signals + 路由懒加载 |
| 视觉风格 | Minimalism / Swiss：单色体系 + 单一强调色、网格对齐、无渐变无投影（仅 1px 边框分层）、数据密度高 |
| 图标 | 全部内联 SVG，禁止 emoji |
| 无障碍 | 正文对比度 ≥ 4.5:1；交互元素可达 44×44；键盘可达；可见 focus ring；状态不只靠颜色 |
| 响应式 | 1440 / 1024 / 768 / 375 四档；侧边栏在 <1024 折叠为抽屉 |
| 性能 | 首屏 ≤ 2s（本地）；路由级代码分割；列表 >50 行启用简单虚拟滚动或分页 |
| 数据 | 纯前端 Mock，确定性、可复现，不含任何真实企业数据（虚构声明置顶显示） |
| 语言 | 中文界面；数字用等宽字体（tabular-nums） |

## 8. 成功指标

| 指标 | 定义 | 目标（待试点验证） |
| --- | --- | --- |
| 抽取准确率 | 与金标准一致的字段 / 已抽字段 | ≥ 90% |
| 抽取召回率 | 已抽到 / 金标准应有 | ≥ 95% |
| 证据定位准确率 | 引用正确 / 抽检 | ≥ 98% |

| 单项目产出时长 | 建项目到发布报告 | ≤ 4 小时 |
| 结论采纳率 | 直接采纳 / 总结论 | ≥ 70% |
| 无引用断言率 | 无证据结论 / 总结论 | ≤ 1% |

## 11. 假设与待确认
