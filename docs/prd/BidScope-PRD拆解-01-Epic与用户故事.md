## E1 项目治理

**目标**：让每个投标项目成为独立的数据与权限单元，并在首页看清「哪些项目在跑、卡在哪」。

### S-01 项目总览 `[D]`
**作为**投标经理，**我要**在首页看到所有在投项目的进度、截止日与风险数量，**以便**决定今天先处理哪个。

**验收标准**
- 卡片展示：项目名、国别、规模(MW/MWh)、截止日倒计时、五阶段进度条、待审数、废标风险数；
- 可按截止日/风险数排序，可按国别与阶段筛选；
- 截止日 ≤7 天的项目有时间紧迫标记（文字 + 图标，不只靠颜色）；
- 空态：无项目时给出「新建项目」主行动。

**数据**：`projects`（3 条）、`reviewTasks` 计数、`riskItems` 计数
**页面**：`/dashboard`、`/projects`

### S-02 项目创建 `[D]`
**作为**投标经理，**我要**创建项目并填规模、国别、技术路线与截止日，**以便**系统加载对应字典与维度。

**验收标准**
- 弹窗表单，字段校验（必填、数值范围、日期不得早于今天）；
- 错误提示显示在字段下方，提交失败时焦点回到首个非法字段；
- 创建成功后出现在列表首位，并生成一条审计事件。

**页面**：`/projects`（弹窗）

### S-03 项目概览 `[D]`
**作为**任何成员，**我要**进入项目后 30 秒内了解资料完整性、阶段进度与风险，**以便**决定下一步动作。

**验收标准**
- 三个信息块：阶段门禁、资料完整性环、风险摘要；
- 每个统计数字可点击跳到对应明细页并带上筛选条件；
- 无招标文件时显示醒目警示条，且对比页禁用「提交审核」。

**页面**：`/projects/:id/overview`

### S-04 成员与权限 `[S]`
**作为**投标经理，**我要**看到项目成员及其角色，**以便**控制谁可编辑、谁只读。

**验收标准**：成员列表含角色徽标与最近活动；角色变更展示在权限矩阵页（只读演示）。

## E2 资料摄取与解析

**目标**：把混杂格式的对手资料变成可定位、可核对的结构化内容，并让「来源是否可靠」可见。

### S-05 资料上传与来源标注 `[D]`
**作为**技术工程师，**我要**上传文件时为每份资料标注类型与来源可靠性，**以便**后续结论能区分「官方发布」与「第三方转述」。

**验收标准**
- 上传抽屉：文件选择（模拟）、类型下拉（招标文件/竞对标书/竞对手册/中标公示/我方资料/其他）、来源四档；
- 未选类型或来源不可提交；
- 提交后进入列表，状态从「排队中 → 解析中 → 完成」模拟推进，并有 Toast 反馈。

**页面**：`/projects/:id/documents`

### S-06 解析状态与质量分 `[D]`
**作为**技术工程师，**我要**看到每份文档的页数、解析状态、质量分与异常提示，**以便**判断哪些结果不能直接信。

**验收标准**
- 表格列：文件、类型、来源、页数、质量分、状态、更新时间、操作；
- 质量分 <70 显示「需人工核对」；解析失败行提供「重试」；
- 可按状态筛选，可排序。

**数据**：`documents`（14 条，含 2 条失败、3 条低分）

### S-07 原文定位与高亮 `[D]`
**作为**技术工程师，**我要**从任何数值跳到原文对应页码并看到高亮片段，**以便**确认模型没有读错。

**验收标准**
- 原文页左右分栏：左侧页面文本（含页码、章节、高亮块），右侧字段锚点列表；
- 点击右侧锚点，左侧滚动并高亮；
- 顶部显示「文件 / 页码 / 章节 / 置信度」；
- 提供「原文理解有误」操作，生成修正建议（不直接改值）。

**页面**：`/projects/:id/documents/:docId`

### S-08 解析异常处理 `[D]`
**作为**技术工程师，**我要**看到缺页、跨页表格、低 OCR 质量等异常，**以便**决定是否人工录入。

**验收标准**：异常以列表 + 严重级展示；每项有「去处理」动作；处理后状态更新。

## E3 参数抽取

**目标**：按行业字典抽出可比参数，并把人的注意力路由到「拿不准的少数字段」。

### S-09 参数草稿矩阵 `[D]`
**作为**技术工程师，**我要**看到按字典抽取的参数矩阵，**以便**快速判断整体质量。

**验收标准**
- 表格列：参数（含字典 key）、来源（我方/竞对）、原始值、标准化值、条件、层级、置信度、状态、证据；
- 置信度以进度条 + 数值呈现；状态用「色 + 图标 + 文字」；
- 支持按维度/来源/状态/置信度区间筛选，支持搜索参数名。

**页面**：`/projects/:id/parameters`

### S-10 置信度路由 `[D]`
**作为**技术工程师，**我要**只看低置信度与冲突项，**以便**把时间花在真正需要判断的地方。

**验收标准**
- 一键筛选「待我确认」（<0.85 或冲突）；
- <0.60 的项标记「强制人工」，不可批量通过；
- 批量确认仅对 0.60–0.85 生效，且需二次确认弹窗。

### S-11 行内修正与理由 `[D]`
**作为**技术工程师，**我要**就地修改数值并选择理由，**以便**修正过程可追溯。

**验收标准**
- 行内编辑：数值、单位、条件；保存后状态变「已修正」，记录操作人与时间；
- 理由为必选（口径不同/原文有误/计算错误/资料过时/行业惯例/其他+说明）；
- 修改后该行出现「已修改」标记，可展开查看历史。

### S-12 冲突裁决 `[D]`
**作为**技术工程师，**我要**看到同一参数在原文的多个取值并裁决，**以便**不让错误值静默生效。

**验收标准**
- 冲突弹窗并列展示各来源值与原文片段；
- 必须选择其一或标记「挂起」，选择需填说明；
- 未裁决的冲突在矩阵中持续高亮，且阻止报告发布。

## E4 标准化与规则校验

**目标**：让不同口径可比，并让「不可比」有机械依据。

### S-13 标准化过程可见 `[D]`
**作为**技术工程师，**我要**查看每个值的换算与映射过程，**以便**相信标准化结果。

**验收标准**：行展开显示「原值 → 别名映射 → 单位换算 → 条件归一 → 标准化值」链路；不可比时显示未通过的四要素检查。

### S-14 规则校验结果 `[D]`
**作为**技术工程师，**我要**看到合理性规则命中的问题（越界、量纲错误、条件缺失），**以便**批量识别脏数据。

**验收标准**：校验问题面板按严重级分组；每条可定位到行；可「忽略并填理由」（留痕）。

### S-15 参数字典维护 `[D]`
**作为**字典管理员，**我要**维护参数定义与别名，**以便**新表述能被自动归一。

**验收标准**：字典表格含 key、名称、单位、层级、必需条件、别名数；新增/编辑走弹窗；变更记录版本号。

**页面**：`/admin`（参数字典 Tab）

## E5 对比与差距分析

**目标**：一张表看清「业主要什么、对手给什么、我们给什么、差在哪、能不能比」。

### S-16 三向对比矩阵 `[D]`
**作为**技术工程师，**我要**在同一行看到招标要求、我方、各竞对的值与判定，**以便**定位差距。

**验收标准**
- 固定列：参数、要求（含 Mandatory 标记）、我方、竞对列（按选择显示）、判定、优先级；
- 判定单元格：状态徽标 + 差异说明 + 证据入口；
- 首列与表头吸顶；行悬停高亮；点击行展开判定理由与规则命中详情。

**页面**：`/projects/:id/comparison`

### S-17 强制条款置顶与废标风险 `[D]`
**作为**投标经理，**我要**第一眼看到可能导致废标的项，**以便**优先处理。

**验收标准**：Mandatory 且非 compliant 的行置顶并带风险标记；顶部显示「废标风险 N 项」并可一键筛选。

### S-18 不可比说明与禁止排名 `[D]`
**作为**技术工程师，**我要**看到「为什么不可比」而不是一个错误排名，**以便**避免错误结论。

**验收标准**
- 不可比行展示四要素差异（层级/单位/条件/边界）与建议澄清话术；
- 页面任何位置不出现「竞对总排名」；只提供分维度对比；
- 权重为默认值时显著提示「默认权重，待确认」。

### S-19 维度权重调整 `[D]`
**作为**投标经理，**我要**按客户评标规则调整维度权重，**以便**得到贴合本项目的热力图。

**验收标准**：权重输入合计必须 100，否则显示错误并禁用应用；应用后热力图与排序即时更新；变更记入审计。

### S-20 差距清单导出 `[D]`
**作为**技术工程师，**我要**导出 CSV/文本清单，**以便**进入标书编制环节。

**验收标准**：导出遵循当前筛选；文件含判定、理由、证据列；导出后 Toast 明确告知范围与行数。

### S-21 我方资料缺失时降级 `[D]`
**作为**技术工程师，**我要**在我方产品库缺型号时看到明确提示，**以便**补资料而不是拿到错误判定。

**验收标准**：缺失时状态为 `noResponse` 并标注「资料缺失」，不计入劣势统计。

## E6 研判与风险

**目标**：在事实矩阵上给出「所以呢」，但严格区分事实、推断、建议。

### S-22 三段式结论卡片 `[D]`
**作为**投标经理，**我要**每条结论都有「结论 / 依据 / 类型」三要素，**以便**评审会当场对质。

**验收标准**
- 类型标签：【事实】必须带证据；【推断】前缀「待核实」；【建议】标明需人决策；
- 每条可「采纳/修改/删除」，修改需填理由；
- 无证据的结论不展示（计入拦截计数并在页面角落显示）。

**页面**：`/projects/:id/insights`

### S-23 风险分级清单 `[D]`
**作为**投标经理/法务，**我要**红黄绿风险清单与处置建议，**以便**安排缓解动作。

**验收标准**：风险含级别、类型、描述、关联参数、建议处置、责任人、状态；可按级别筛选；高风险默认展开。

### S-24 待澄清问题清单 `[D]`
**作为**技术工程师，**我要**导出澄清问题草稿，**以便**在答疑窗口提交。

**验收标准**：每条含问题、背景、影响项、来源证据；可勾选后复制为文本。

### S-25 决策留白 `[D]`
**作为**系统，**我要**在涉及报价与承诺的位置留空占位，**以便**责任边界清晰。

**验收标准**：页面出现「报价让利空间：____」「承诺可用率：____」等占位输入框，由人填写；AI 生成区不出现具体数字承诺。

### S-26 研判门禁 `[D]`
**作为**系统，**我要**在已确认字段不足时拒绝生成研判，**以便**防止基于脏数据出结论。

**验收标准**：已确认 <15 项时禁用生成，列出待确认缺口链接。

## E7 审核与协作

**目标**：让人的判断成为唯一生效路径，并留下完整证据链。

### S-27 我的待办 `[D]`
**作为**审核人，**我要**在待办里看到分配给自己的任务及截止时间，**以便**按时完成关卡。

**验收标准**：任务卡片含类型、优先级、目标、截止、发起人；超期任务有标记；支持筛选与指派。

**页面**：`/projects/:id/reviews`

### S-28 Diff 审核 `[D]`
**作为**审核人，**我要**看到「AI 建议 vs 当前值」的差异，**以便**只审变化部分。

**验收标准**：左右 diff 视图；变更行高亮；可逐条采纳/驳回；批量采纳仅对低风险开放。

### S-29 双人规则 `[D]`
**作为**系统，**我要**拒绝编辑人自审高风险项，**以便**避免既当运动员又当裁判。

**验收标准**：自审时按钮禁用并说明原因；需指定第二审核人。

### S-30 审核留痕与版本 `[D]`
**作为**管理层，**我要**看到谁在何时改了什么、理由是什么，**以便**事后追溯。

**验收标准**：时间线视图；每次状态变更含操作人/时间/理由；可按字段或结论过滤。

## E8 报告与导出

**目标**：一次分析服务三种受众，且导出内容可回溯。

### S-31 报告模板选择 `[D]`
**作为**投标经理，**我要**选择技术报告/差距清单/证据索引/澄清清单/一页简报，**以便**匹配不同读者。

**验收标准**：模板卡片含适用对象、章节数、预计页数；选择后显示预览。

**页面**：`/projects/:id/reports`

### S-32 发布门禁与水印 `[D]`
**作为**系统，**我要**阻止含未审项的报告导出，**以便**不把草稿当结论。

**验收标准**：未审项 > 0 时导出按钮禁用并列出清单；导出内容带项目名/导出人/时间水印。

### S-33 一页简报 `[D]`
**作为**管理层，**我要**一页纸看懂结论、胜负手、风险与待决策项，**以便**5 分钟决策。

**验收标准**：简报含一句话结论、3 条胜负手（各带证据）、红黄绿风险、留空决策项、证据索引数。

### S-34 导出记录与审计 `[D]`
**作为**管理员，**我要**看到所有导出行为，**以便**满足保密审计。

**验收标准**：审计日志含导出对象、范围、操作人、时间、IP；可筛选「导出」类事件。

## E9 竞品情报与系统管理

### S-35 竞对档案 `[D]`
**作为**技术工程师，**我要**查看某竞对的历史参数与参与项目，**以便**复用而非重做。

**验收标准**：档案页含梯队、区域、代表型号、参数时间线（含来源与有效期）、参与项目与中标情况；过时（>18 个月）数据带标记。

**页面**：`/library`

### S-36 情报检索 `[D]`
**作为**技术工程师，**我要**按竞对/参数/区域检索历史情报，**以便**快速定位。

**验收标准**：关键词 + 维度筛选；结果高亮匹配项；空态给出检索建议。

### S-37 权限矩阵 `[D]`
**作为**管理员，**我要**配置角色与操作权限，**以便**满足最小可见原则。

**验收标准**：矩阵表可切换单元格权限并保存；保存写入审计；管理员不可读正文的限制在界面说明。

**页面**：`/admin`

### S-38 阈值与字典、审计日志 `[D]`
**作为**管理员，**我要**调整置信度阈值、抽检比例与维度权重，并查看审计日志，**以便**持续运营。

**验收标准**：阈值表单含范围校验与「恢复默认」；修改需填写变更说明；审计日志可按类型/操作人/时间筛选。

## 附录 A · 全局状态机

```
参数实例：抽取中 → 待复核 → (已确认 | 已修正 | 冲突待决) → 已发布
审核任务：待处理 → (已通过 | 已驳回 | 已指派 | 已超期) → 已归档
报告：草稿 → 待审 → 已发布(快照, 只读) → 已导出
```

## 附录 B · Definition of Done（每个故事）

1. 路由可直达，刷新不丢；
2. 有 Mock 数据支撑，非硬编码文本；
3. 加载 / 空 / 异常三态齐全；
4. 键盘可操作，焦点可见，状态不只靠颜色；
5. 无 emoji，图标为内联 SVG；
6. 1440/1024/768/375 四档无横向滚动、无内容遮挡；
7. 控制台零报错。
