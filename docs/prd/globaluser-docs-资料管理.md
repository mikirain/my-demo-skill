## 1. 页面目标

**解决的问题**：一份 25MW/100MWh 大储投标，竞对资料通常是 3 家 × 200–300 页的多语种 PDF，其中夹杂扫描件、跨页参数表、曲线图与铭牌照片。资料进入系统前若不把「这是谁的文件、从哪来、能不能信、解析成不成」这四件事固定下来，后续参数矩阵的每一个数字都会失去证据链。本页是整个 F2 的**收料台与质量闸门**：进来的资料必须有类型、来源可靠性与语言；出去的资料必须有页码、质量分与解析状态。

**具体目标**

1. 把上传动作压缩到一次抽屉提交（文件 + 类型 6 选 + 来源可靠性 4 档 + 语言），提交即入解析队列，不要求用户先建目录。
2. 用一张表让工程师在 30 秒内回答「哪些资料能用、哪些要人看、哪些失败了」，并把失败与低质量分转成可执行动作（重试 / 去处理 / 替换 / 标记已处理）。
3. 把解析异常从「黑箱失败」变成四种可命名、可定位到页码、有明确处理路径的工单。
4. 让每一份资料都能被追溯到来源与哈希，满足对质原文的要求（BR-01）。

**成功标准**

| 编号 | 标准 | 度量 |
| --- | --- | --- |
| S-01 | 上传必填项缺失时 100% 拦截并标红定位到字段 | 表单校验覆盖率 |
| S-02 | 质量分 < 70 的资料 100% 带「需人工核对」标记，且不会静默进入对比结论 | 抽查 20 份 |
| S-03 | 解析失败行 100% 可一键重试，重试后状态按状态机推进且留痕 | 失败行覆盖 |
| S-04 | 每条解析异常都能落到「类型 + 页码 + 处理路径」三要素 | 异常项完整率 |
| S-05 | 单项目 5 份资料的首屏呈现 ≤ 1.5 秒（Mock），状态轮询不打断阅读 | 手工计时 |
| S-06 | 只读角色在本页零写入控件渲染 | 角色走查 |

**非目标**：不在本页做参数复核、不做对比判定、不做竞对档案编辑、不做全文检索（分别在参数矩阵、对比分析、竞品情报库、原文查看）。

## 2. 适用角色与权限

依据主 PRD 第 17.3 节，资料管理一行为：工程师 **编辑**、投标经理 **编辑**、商务 **只读**、法务 **只读**、管理层 **—**、知识库管理员 **只读**、系统管理员 **只读**、只读观察者 **只读**。

**三条硬约束在本页的落地**：只读角色不渲染写入控件（不是禁用）；系统管理员（`admin`）不可读取文档正文，只能看元数据；任何写入都产生审计事件。

补充说明：

- **管理层**：本页整页不可见。侧栏项目分组中不出现「资料管理」；直链进入显示 404 页变体「权限不足」，正文为「资料管理仅对项目成员开放，当前角色为管理层。如需查看解析质量，请前往报告中心的证据索引。」并给「返回项目列表」。
- **只读观察者**：登录后顶栏下常驻提示条「当前为只读视角，写入操作不可用」，本页无 primary 按钮，只有 4 类只读操作（查看原文、下载原件、来源详情、复制证据链接）。
- **商务 / 法务 / 知识库管理员**：可看到全部行与全部列，用于核查证据来源；但不出现上传、重试、批量、删除入口，行尾操作区只剩 3 个链接（原文、下载、来源详情），视觉上不留空按钮位。
- **系统管理员**：能进本页是因为需要核对「谁在什么时候上传了什么」的审计链，但**不渲染原文与下载**；在「来源详情」弹窗底部给一行灰字「系统管理员不读取文档正文（F10）」。管理员看不到本页的原文跳转入口，这一点必须与原文查看页（对 admin 为 `—`）保持一致。

## 3. 进入与离开

**入口**

| # | 入口位置 | 触发 | 携带参数 |
| --- | --- | --- | --- |
| 1 | 侧栏「当前项目」分组 › 资料管理 | 点击 | 无 |
| 2 | 项目概览 › 摄取门禁卡（「每份文档有来源可靠性」） | 点击「去补来源」 | `?status=review` |
| 3 | 项目概览 › 待处理区「解析失败 N 份」 | 点击 | `?status=failed` |
| 4 | 投标工作台 › 今日待办「doc-13 解析失败，需重试」 | 点击 | `?status=failed&doc=doc-13`（定位并高亮该行） |
| 5 | 项目列表 › 项目卡片菜单「资料」 | 点击 | 无 |
| 6 | 竞品情报库 › 竞对档案「该竞对在本项目有 1 份失败资料」 | 点击 | `?type=competitorBid&q=竞对E` |
| 7 | 经验库 › 等级升级申请（LR-01 需补证据来源） | 点击「上传证据材料」 | `?upload=1&link=exp-03` |
| 8 | 通知（IM/站内）「解析任务已完成 3 份」 | 点击 | `?status=done` |
| 9 | 原文查看 › 面包屑「资料管理」 | 点击 | 保留上次筛选（URL 记忆） |

**离开**

| # | 去向 | 触发 | 携带参数 |
| --- | --- | --- | --- |
| 1 | 原文查看 `/projects/[projectId]/documents/[docId]` | 点文件名或「查看原文」 | `?page=11&from=documents&issue=iss-01` |
| 2 | 参数矩阵 `/parameters` | 质量分 < 70 行的「查看受影响参数」 | `?doc=doc-04&filter=lowQuality` |
| 3 | 项目概览 `/overview` | 面包屑或摄取门禁回链 | `?gate=ingest` |
| 4 | 竞品情报库 `/library` | 来源详情弹窗「查看该竞对档案」 | `?competitor=c-a&tab=timeline` |
| 5 | 系统管理 › 审计日志 `/admin?tab=audit` | 「来源详情 › 最近变更」 | `?entity=doc-04`（仅系统管理员、投标经理可见该入口） |
| 6 | 404 权限不足页 | 管理层直链 | `?from=documents&reason=role` |

**URL 参数约定**：`status`（queued/parsing/done/review/failed）、`type`（6 类）、`q`、`sort`（updatedAt/pages/qualityScore）、`dir`（asc/desc）、`doc`（高亮行）、`issue`（高亮异常项）、`upload=1`（自动打开抽屉）。返回本页时筛选、排序、分页必须从 URL 恢复（`globaluser.md` 6.7 状态保持）。

## 7. 交互细节

**筛选与排序**

- 状态 chips 为单选，选中后 chips 下方表格即时过滤，chips 计数基于**当前其它筛选条件之外的全量**（便于用户理解「失败 0」是真实为 0）。
- 搜索框匹配文件名与哈希（不区分大小写），输入 300ms 防抖；匹配片段在文件名中高亮（`--accent-weak` 底）。
- 类型、来源可靠性为单选下拉，默认「全部」；三个筛选条件之间为 AND。
- 排序：默认更新时间 desc；点击「页数 / 质量分 / 更新时间」表头切换 asc/desc，箭头 12px；质量分排序把 `—` 恒置末尾（不当作 0）。
- 任一筛选生效时，筛选条右侧出现「清空筛选」文本按钮，并显示「筛选结果 2 / 5」。

**上传抽屉**

1. 打开时焦点落在文件区；Esc 或点遮罩关闭，已填内容保留在页面内存 1 次（再次打开恢复，关闭页面清除）。
2. 选择「来源可靠性」后，字段下方展开该档的一句话定义（与来源详情弹窗同文案），来源链接字段按需变为必填（标红星号即时出现）。
3. 类型选择「竞对标书 / 竞对手册」时，「关联竞对」从隐藏变为必填并展开。
4. 提交校验顺序：文件 → 类型 → 来源可靠性 → 语言 → 条件字段；首个错误字段获得焦点并在字段下方显示 12px 红字 + alert 图标；同时 Toast「表单校验未通过，请检查 2 处必填项」。
5. 提交成功后抽屉关闭，页面自动把状态筛选重置为「全部」，新行置顶，状态「排队中」，并 Toast「资料已进入解析队列：CZ-Morava_RFP_补充附件.pdf」。
6. 同名同哈希：不直接入队，弹出确认「该文件已存在（doc-02，2026-10-15 上传）。作为新版本上传将保留历史版本。」→ 取消 / 作为新版本上传。
7. 批量上传：≤10 个文件，逐个入队；单文件失败不影响同批其他文件（NFR-03），抽屉底部给汇总「8 份已入队，1 份格式不支持」。

**解析异常面板**

- 按严重度分组：高风险 → 中风险 → 低风险，组头显示徽标 + 项数；组内按页码升序。
- 每项右侧两个按钮：「去处理」（secondary）、「标记已处理」（ghost）。「去处理」打开 md 560 弹窗，展示异常类型、页码、涉及资料、检测描述与 **3 步处理路径**，底部为「取消 / 标记已处理」。
- 「标记已处理」需在弹窗内确认，勾选「已按处理路径核对」才启用按钮，避免误点清空风险；提交后 Toast「异常已标记处理：P.11 缺页」，审计记 `人 / 时间 / 异常 id`。
- 面板右上角计数「共 N 项待处理」，点击等值于筛选「只看未处理」。
- 异常项与资料行双向关联：点异常项中的文件名，表格滚动并高亮该行 1.5 秒（`--accent-weak` 底）。

**场景组 1：缺页导致「可用率」判定失真（doc-04）**

- 参数：可用率保证；招标要求「年可用率 ≥98%，按时间加权统计」（doc-01 P.14）；竞对 D 中标文件中该值出现在 P.12。

- 判定：参数矩阵该行为「证据不足」（灰 help），不得写「竞对 D 未承诺可用率」。
- 理由：缺页属于解析侧缺失，按 BR-03 不得推断为对方未披露。
- 处理：处理路径第 1 步向招标方索取原始公示 PDF → 重新上传为「中标公示 / 第三方转述」→ 补齐 P.12 后异常关闭，质量分 81。

**场景组 2：低质量分 + 来源未知的扫描件（doc-13）**

- 文档：竞对E_技术应答_扫描件.pdf，178 页，200 dpi 灰度扫描，语言英文，来源「来源未知」，诊断评分 41，状态「失败」。
- 失败原因：文本层为空，OCR 均置信度 0.46（阈值 0.80），解析中止。
- 用户动作：重试 2 次仍失败 → 「更多 › 替换文件」上传 300 dpi 解密版 → 状态 排队中 → 解析中（P.131/178 · 74%）→ 完成，质量分 88。
- 结果：抽取到 PCS 效率 98.6%（P.44，条件 25℃、半载），但因来源未补链路，参数矩阵仍标「来源未知，不得单独作为判定依据」；工程部在来源链接栏补「客户提供的投标文件副本，2026-10-23 由区域销售转交」。

**场景组 3：跨页表格把表头与数值错行（doc-02）**

- 文档：竞对A_技术应答文件_v2.pdf，P.37–P.38 的技术参数表断裂，P.37 尾行为「Round trip efficiency」，P.38 首行为「92%（DC terminals）」。

- 处理：核对两张表的表头继承关系无误 → 保持「已处理」；在对比分析生成澄清「提请业主统一效率测量边界与辅助功耗口径」。

**场景组 4：曲线图里的循环寿命不得目视估读（doc-08 / doc-02 P.54）**
