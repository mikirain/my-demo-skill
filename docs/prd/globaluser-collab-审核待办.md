## 1. 页面目标

### 1.1 解决什么问题

系统在阶段间产出大量「建议值」：参数从 0.61 置信度的抽取值被修正为 0.90、强制条款从「无法直接比较」被建议改为「满足」、结论从「推断」被建议改为「建议」。这些建议如果直接生效，会产生两类事故：

1. **口径被悄悄改写**：把「88.5%（AC-AC，不含辅助）」改成「88.5%（AC-AC，含辅助）」，字面上只多四个字，实际改变了可比较性，进而改变偏离表结论；
2. **责任无法追溯**：评审会被问「这条结论谁批的、依据什么」，若只有一句「系统建议」，团队无法对质原文。

F7 的定位是：**人的判断是唯一生效路径，且每一次生效都留痕**。本页是该路径的操作台，只做三件事——把待审项排好队、把「当前值 vs 建议值」摆在同一个屏幕上、把「谁批的、凭什么」记下来。

本页不生成新结论、不做批量重算、不替代法务判断承诺边界（BR-06 决策留白在此体现为「承诺类字段只能由法务角色确认，系统不给推荐值」）。

### 1.2 对应功能编号

- 主功能：**F7 审核与协作**（主 PRD 6.3），验收口径沿用「高风险 100% 可追溯审批人；无自审通过」；
- 关联功能：F3 参数抽取（低置信度字段在此入队）、F5 对比差距（强制条款判定在此确认）、F6 研判风险（结论类型与措辞在此落定）、F8 报告导出（未审项阻断发布）、F9 竞品情报库（入库申请在此审批）、F12 经验库（等级变更审批走同一套双人规则，但界面在经验库页）。

### 1.3 成功标准

| 编号 | 标准 | 目标值 | 度量方式 |
| --- | --- | --- | --- |
| S-01 | 高风险任务有审批人且审批人 ≠ 提交人 | 100% | 抽检审核记录 |
| S-02 | 采纳 / 驳回均带理由或快捷项 | 100%（采纳低风险可免理由，见 7.5） | 审核记录字段完整性 |
| S-03 | 单任务从打开到提交的中位时长 | ≤ 90 秒（低风险）/ ≤ 4 分钟（高风险） | 埋点 |
| S-04 | 超期任务数占比 | ≤ 10%，且超期 24 小时内必有升级动作 | 列表统计 |
| S-05 | 采纳后被下游回退（报告导出时发现未审 / 字段被二次修正） | ≤ 5% | 审计事件比对 |
| S-06 | 人工复核率（KPI-07） | 首月 ≤ 40%，三个月 ≤ 25% | 待办字段 / 总字段 |

### 4.3 视觉层级与信息密度

- **一级**：任务标题 + 建议值中新值（唯一允许使用 `--accent` 的位置是「建议值」与主按钮）；
- **二级**：字段名、当前值、diff 变更标记（3px 左侧强调条 + `已变更` 文字，不靠颜色单独表达）；
- **三级**：提交人、指派、来源链接、时间线；
- 列表与详情**各自独立滚动**，选中项左侧 3px 强调条 + `--bg-subtle` 底，快捷键 J/K 切换时列表自动滚动到可视区；
- 数字全部 `tabular-nums`：置信度 `0.61`、页码 `P.37`、时长 `88 周`、`DoD 90%`；
- 单屏信息上限：列表同时可见 3 张任务卡；详情默认只展示 diff，时间线收起（长内容折叠，见 8.5）。

| 变更标记 | 已变更 / 未变更 | 行首图标：edit（已变更）/ minus（未变更）+ 文字，第三重编码为左侧 3px 竖条 |
| 单位与条件 | `%` / `AC-AC，含辅助` | 单位不得省略；条件缺失显示「条件未标注」且不可参与比较（第 7.2 节） |
| 证据 | P.37 §4.2 表 4-3 | 可点击，跳原文锚点；无证据显示「无引用」灰 chip（BR-01） |
| 变更前证据 | P.30 表 5-1 | 仅当建议值更换了证据来源时出现 |

### 5.4 任务类型字典（决定行动条与校验）

| 类型 | 典型来源 | 是否可批量 | 附加字段 | 特殊约束 |
| --- | --- | --- | --- | --- |
| 参数复核 | 参数矩阵（F3/F4） | 低风险可批量 | 参数 ID、置信度、条件、单位 | 冲突待决项不可批量；采纳后回写参数矩阵 |

## 7. 交互细节

### 7.1 筛选与排序

- 筛选维度：状态、优先级、类型、指派（含「指派给我」）、关键词（匹配标题 / 字段名 / 目标编号）；
- 多选状态用 chip 式多选（待处理 + 已超期 可同选，语义为并集），筛选条右侧显示「已选 3 个条件 · 清空」；
- 排序：截止时间（默认，升序）、风险（高→低）、提交时间（新→旧）；排序切换写 URL `?sort=due`；
- 筛选结果为空时不显示「无数据」，显示「当前条件下没有任务」+「清空筛选」主行动（见 8.2）。

### 7.2 diff 展开与阅读

- 默认展示全部差异行（上限 12 行，超出内部滚动，表头吸顶）；
- 长文本 diff（结论措辞类）按**词级**高亮：新增词 `--accent-weak` 底 + 下划实线，删除词灰底 + 删除线；不整行染色；
- 单位或条件发生变化的行，行尾追加 `!` 图标 + 文案「口径变化」；hover 展开「变更影响」：`该字段条件由「未标注」变为「DoD 90%」，变化后可与招标要求直接比较`；
- 冲突待决任务在 diff 上方插入**裁决条**：`发现 2 个来源值，需先裁决` + 两个来源卡片（值 / 条件 / 文件 / 页码 / 可靠性），选择其一后「采纳」才可用（BR-07 冲突不消解，系统不替人消解）；
- 「未变更」行可折叠（默认展开），折叠后显示「另有 1 行未变更」。

### 7.3 双击 / 行内操作

本页不做行内编辑。所有写操作走行动条，理由与审批意见集中在理由区，避免「diff 里改了但没记理由」。

### 7.4 弹窗与抽屉

| 场景 | 形式 | 尺寸 | 关键内容 |
| --- | --- | --- | --- |
| 指派第二审核人 | 弹窗 | sm 420 | 搜索 + 成员列表（姓名 / 角色 / 当前待办数）；不含权限者置灰并说明「需审核权限」 |
| 批量采纳确认 | 弹窗 | md 560 | 条目清单（编号 + 标题 + 风险）、「共 3 条，均为低风险」、理由（统一理由，可逐条覆盖）、确认按钮文案「确认采纳 3 条」 |
| 驳回 | 弹窗 | md 560 | 快捷项多选 + 理由文本域（≥10 字）+ 「驳回后目标对象保持不变」提示 |
| 超期升级确认 | 弹窗 | sm 420 | 「将升级至 王琛（投标经理），并在时间线记录」 |
| 冲突裁决 | 弹窗 | md 560 | 两/三个来源并排，选值 + 理由 |

弹窗统一：Esc 关闭、焦点回到触发元素、遮罩 40% 黑、无进出场动效（仅 120ms 透明度）。

### 7.5 理由快捷项与必填校验

| 动作 | 必填 | 最小长度 | 快捷项 | 校验文案 |
| --- | --- | --- | --- | --- |
| 采纳 · 低风险 | 否 | 0 | 口径已核对 / 证据充分 / 仅格式修正 / 与原文一致 | — |
| 采纳 · 中风险 | 是 | ≥6 字 | 同上 + 条件已归一 / 已确认与招标一致 | 「请填写理由（≥6 字），将写入审核记录」 |
| 采纳 · 高风险 | 是 | ≥10 字 | 已核对原文并确认口径 / 已与法务确认边界 / 已与商务确认口径 | 「高风险项理由需 ≥10 字，需说明依据来源」 |
| 驳回 | 是 | ≥10 字 | 证据不足 / 条件缺失 / 口径不可对齐 / 建议值错误 / 超出承诺边界 / 需补充原文 | 「驳回必须说明原因，便于提交人重做」 |
| 指派 | 是 | ≥4 字 | 超出本人权限 / 需法务确认 / 需商务确认 / 跨专业 | 「请说明指派原因」 |
| 批量采纳 | 是（统一） | ≥6 字 | 均为低风险格式项 / 均已核对原文 | 同上 |

快捷项点击后把文案填入文本域（可继续编辑），再次点击取消；快捷项是「预填文本」，不是唯一答案，避免理由被模板化。理由写入审核记录后**不可编辑**，只可追加评论。

### 7.6 双人规则（BR-08）

触发条件：`风险 = 高` 且 `当前登录人 = 提交人`。

- 「采纳并提交」「驳回」两按钮进入 `disabled`，`aria-disabled=true`，按钮下方常驻一行说明：
  `高风险项需第二审核人：该任务由你提交，不能自行批准。请指派王琛（投标经理）或陈立（法务）复核。`
- 行动条同时渲染「指派第二审核人」按钮并轻微强调（描边加重），使路径唯一且明确；
- 指派完成后，按钮文案变为「已指派 王琛 · 等待复核」，任务转「已指派」，`指派审核人` 字段更新；
- 若不满足指派权限（工程师），提示改为：`请联系王琛（投标经理）指派第二审核人。` 并给「复制说明」；
- 后端二次鉴权：即使前端被绕过，服务端对 `提交人 == 操作人 && 高风险` 返回 403，前端就地错误条（8.3），任务状态不变；
- 同一规则适用于入库申请的审批与经验库等级变更（LR-04），文案一致以便用户形成统一认知。

### 7.7 批量采纳

- 入口：列表卡片左侧复选框（仅低风险任务渲染复选框；高/中风险卡片**没有**复选框，hover 时给「高风险不支持批量」的灰字说明）；
- 选中 ≥1 条后列表底部浮出批量条：`已选 3 条 · 均为低风险` + 「批量采纳」+「取消选择」；
- 若用户通过「全选」试图纳入高/中风险，全选仅选中可批量项，并提示 `已跳过 2 条非低风险任务`；
- 点击「批量采纳」→ 二次确认弹窗，逐条列出编号与标题，确认按钮文案含数量；
- 提交顺序执行，逐条返回结果：成功 N 条、失败 M 条（失败给原因与「重试失败项」）；部分成功时列表状态即时更新，不清空筛选。

### 7.8 审核记录时间线

- 事件类型：任务创建、指派、评论、采纳、驳回、超期升级、撤回（提交人撤回重做）、字段被下游二次修正；
- 每条显示：`11-06 14:32  王琛（投标经理）  采纳  ·  理由：已核对原文 P.37 表 4-3` ；
- 时间线支持按事件类型过滤，默认「全部」；超过 8 条折叠为「展开全部 12 条」；
- 时间线是只读的，不可删除；对已通过任务的追加评论允许，标注「补充说明」。

## 8. 状态覆盖

### 8.1 加载

- 列表骨架：6 张卡片占位（每张 84px，含两条灰块），不做整页 spinner；
- 详情骨架：任务头 96 + 3 行 diff 占位 + 行动条占位；
- 超过 800ms 未返回时，在列表顶部出现一行 `正在加载审核任务…`（仅文字，不阻塞）；
- 骨架期间快捷键失效，避免误操作。

### 8.2 空态（四种，均给一个主行动）

| 场景 | 文案 | 主行动 |
| --- | --- | --- |
| 项目无任何审核任务 | 图标（check）+ `本项目暂无审核任务` + `所有建议值已处理完毕，或尚未生成建议` | 「去参数矩阵核对低置信度字段」 |
| 筛选无结果 | 图标（search）+ `当前条件下没有任务` + `已选：状态 待处理 · 优先级 高` | 「清空筛选」 |
| 「指派给我」为空 | `没有指派给你的任务` + 小字 `可切换为「全部」查看本项目 6 条任务` | 「查看全部」 |
| 全部处理完成（本批） | 图标（check）+ `本批 6 条已全部处理` + 汇总 `采纳 5 · 驳回 1 · 用时 22 分钟` | 「去报告中心发布」 |

空态不显示伪造的「0 条」计数条；统计条隐藏。

### 8.3 错误

- 提交失败：行动条上方就地错误条（红色 1px 边框 + alert 图标 + 文案 + 「重试」），`未保存，任务状态未变更`，保留用户已填理由；
- 403（双人规则被服务端拦截）：`你提交了该高风险项，不能自行批准（BR-08）。请指派第二审核人。`；
- 409（他人已处理）：见 7.10，附「刷新」；
- 目标对象版本冲突：`目标对象已被修改，建议值过期` + 「查看差异」；
- 数据加载失败：列表区显示 `审核任务加载失败` + `错误码 R-503` + 「重试」；右栏保留上一次内容并标灰，避免闪白。

### 8.4 无权限

- 直链进入但角色为管理层 / 知识库管理员 / 系统管理员 / 只读观察者：走 404 变体页，标题 `无权访问审核待办`，正文 `审核涉及结论与证据定级，仅技术投标工程师与投标经理可进入。当前角色：管理层（赵晗）。`，动作「回到工作台」+「切换角色」；
- 商务 / 法务可进入但只读：页面顶部常驻灰条 `只读视角：可查看差异与审核记录，审核操作需投标经理或技术投标工程师权限`，行动条不渲染；
- 工程师尝试指派：不渲染按钮，溢出菜单中给灰字 `需投标经理权限`。

### 8.5 长内容

| 长内容 | 处理 |
| --- | --- |
| diff 超过 12 行 | 内部滚动，表头吸顶；顶部提示 `共 16 行差异，建议逐段核对` |
| 单行值超长（结论措辞 300 字） | 折叠 3 行 + 「展开全文」；展开后行高自适应，不撑破栏宽 |
| 理由超 200 字 | 文本域限 200 字，超出禁止输入并显示 `200/200`，不静默截断 |
| 时间线超过 8 条 | 折叠 + 「展开全部」；超过 50 条改为分页（每页 20） |
| 任务标题超 48 字 | 单行省略 + title tooltip，详情页完整展示（允许 2 行） |
| 列表 9 条以上 | 每页 20，分页条常驻；不虚拟滚动（保证 Ctrl+F 可搜） |

## 9. 规则引用

| 规则 | 本页落地表现 |
| --- | --- |
| BR-01 证据优先 | 每个 diff 行必须有证据入口；证据为空显示「无引用」灰 chip，该行不可单独采纳（按钮禁用并提示「该建议无原文引用」） |
| BR-02 缺失不等于零 | 当前值缺失显示 `—` + tooltip「原文未披露」；建议值不得为 `0` 或 `—`，否则提交按钮禁用 |
| BR-03 未披露不等于不具备 | 类型为「参数复核」且当前值为「未披露」时，建议值只能是「未披露（维持）」，不得改为「不具备」 |
| BR-04 不可比不排名 | 采纳把判定从 `incomparable` 改为 `compliant` 时，弹窗提示 `修改后该行将参与排名，请确认口径已归一（BR-04）` |
| BR-05 强制条款置顶 | 「强制条款」类任务在列表中始终排在同风险等级的最前；采纳为 compliant 后仍需在对比分析可见；非 compliant 时任务头显示 `关联废标风险清单` 链接 |
| BR-06 决策留白 | 承诺类任务：系统只给「当前条件」与「建议补充附件」两类占位，标记 `需法务确认`；工程师与投标经理的采纳按钮禁用 |
| BR-07 冲突不消解 | diff 含冲突待决字段时插入裁决条，多值全部保留；未裁决不可采纳；裁决理由进时间线 |
| BR-08 双人规则 | 见 7.6：高风险 + 提交人=本人 → 采纳 / 驳回禁用 + 指派引导；服务端二次拦截 |
| BR-09 修正可审计 | 每次采纳写审计事件 `approve`，含原值、新值、操作人、时间、理由、目标版本；时间线可查 |
| BR-10 置信度路由 | 任务头显示置信度 chip：`0.61 强制人工`（<0.60 或冲突）/ `0.72 提示复核`（0.60–0.85）/ `0.88 抽检`（≥0.85）；`≥0.85` 且低风险的任务默认不进「待处理」，仅在「抽检」筛选中出现 |
| BR-15 引用留痕 | 入库申请类任务通过后，时间线记录 `引用至 企业知识库 · 有效期 18 个月`，并在竞品情报库可见 |
| LR-03 理由 ≥6 字 | 理由校验的下限来源；高风险 / 驳回取更严的 ≥10 字，见 7.5 |

## 10. 真实场景内容

> 以下项目、竞对、参数编号与 `globaluser.md` 5.2 节一致：`p-01` CZ-Morava 25MW/100MWh（主项目）、竞对 A/B/C、`pv-019`、`cmp-001`、`ins-006`、`risk-03`。数值与页码为虚构演示数据。截止时刻在原 mock 基础上做了微调，用于覆盖「已超期」两种触发路径（跨日超期与 SLA 内超期）。

### 10.1 场景一：高风险强制条款 + 双人规则触发（task-02）

**背景**：对比分析中 `cmp-001`「系统往返效率 ≥88%（AC-AC 全系统）」被判定为「无法直接比较」，系统建议改为「满足」，理由是我方 88.5% 的口径实际含辅助功耗，与招标要求边界一致。

| diff 字段 | 当前值 | 建议值 | 证据 |
| --- | --- | --- | --- |
| 判定 | 无法直接比较（虚线边框 + scale 图标 + 文字） | 满足（实线边框 + check 图标 + 文字） | cmp-001 |
| 我方展示值 | 88.5%（AC-AC） | 88.5%（AC-AC，含辅助） | 我方规格书 P.12 表 2-1 |
| 招标要求边界 | AC-AC 全系统（含辅助） | AC-AC 全系统（含辅助） | 招标文件 P.37 §4.2 表 4-3 |
| 证据 | P.37 §4.2 表 4-3 | 未变更 | — |

**用户会怎么用（李维，技术投标工程师）**：李维在工作台「我的待办」看到 `系统往返效率强制条款判定`，点击进来。右栏顶部已有一条黄色说明 `高风险，截止 2026-10-24 14:00，已超期 4 小时 12 分`。他先点「我方展示值」行的证据链接，跳到原文 P.12 表 2-1，确认 88.5% 的脚注写着「含 HVAC 与 BMS 辅助功耗，AC-AC 计量」。回到审核页，理由区点快捷项「已核对原文并确认口径」，补一句「脚注 P.12 注 3 明确含辅助」。此时他发现「采纳并提交」是灰的，下方一行灰字：`高风险项需第二审核人：该任务由你提交，不能自行批准。请指派王琛（投标经理）或陈立（法务）复核。` 他没有指派权，于是点「复制说明」发到 IM 群。五分钟后王琛从通知进来，diff 与证据都在同一屏，点「采纳并提交」，理由自动带入李维的说明 + 自己的 `已与商务确认对外口径一致（BR-04 允许参与排名）`。任务转「已通过」，时间线新增两条，对比分析该行判定同步变为「满足（实线 + check + 文字）」。

### 10.2 场景二：循环寿命冲突待决（task-01）

**背景**：`pv-019` 竞对 A 循环寿命，投标文件与产品手册给出两个值。

| diff 字段 | 当前值 | 建议值 | 说明 |
| --- | --- | --- | --- |
| 值 | 12000 次（投标文件 P.42 表 6-1） | 12000 次 | 与手册值冲突，需裁决 |
| 条件 DoD | 未标注 | 90% | 手册标注，投标文件未标 |
| 条件 SoH | 未标注 | 70% | 同上 |
| 温度 | 25℃ | 25℃ | 两份一致 |
| 置信度 | 0.61 | 0.90 | 裁决后重算 |
| 状态 | 冲突待决（红 + alert + 文字） | 已确认 | 采纳后生效 |
| 来源 2 | 产品手册 P.30 表 5-2：10000 次 @DoD90/25℃/SoH70 | 保留为待裁决 | 不因采纳而删除（BR-07） |

**处理要求**：直接点「采纳」不可行，diff 上方有裁决条 `发现 2 个来源值（12000 / 10000），需先裁决`。裁决弹窗并排展示两份来源：投标文件（来源可靠性：公开投标摘要，P.42）、产品手册（官方手册，P.30），下方一行 `两个值均保留在参数时间线，未被选中的值标记为「未采用」`。李维选择 10000 次（手册条件完整），理由 `投标摘要条件缺失，采用手册完整条件值`。采纳后 `pv-019` 在参数矩阵显示 `10000 次 @DoD90/25℃/SoH70`，另一值进入竞品情报库时间线。

### 10.3 场景三：承诺风险超期升级（task-04）

**背景**：`risk-03`「循环寿命承诺条件」建议把 `DoD 90%/25℃/SoH 70%` 写入合同附件，属承诺类（BR-06）。

**用户会怎么用（陈立，法务）**：陈立从通知进入，看到截止 `2026-10-24 12:00`、`已超期 7 小时`，状态标红加粗。承诺类任务的行动条只有「采纳并提交」一个可用按钮（工程师与投标经理均被禁用），他点开证据确认招标文件 P.51 §9.3 的容量保证条款确实以「合同附件」为准，填写理由 `已在合同附件草案 §4.2 写入该条件，与招标 P.51 §9.3 一致`（38 字），提交。随后他点「标记超期升级」，确认弹窗显示 `将升级至 王琛（投标经理），并记录超期 7 小时 12 分`，时间线出现 `超期升级 · 陈立 → 王琛 · 原因：跨专业确认耗时`。王琛次日在工作台看到该条，复盘时据此调整了本项目的 SLA 提醒策略。

### 10.5 场景五：入库申请（task-06）与来源过期（task-09）

## 11. 验收标准

- [ ] 页面在 1440×900 下左列表 400px、右详情 ≥560px 无横向滚动；1280 宽下左列表收窄至 360px，diff 双栏仍不折行错位。
- [ ] 左列表每条任务同时显示：类型、优先级、截止时刻、超期标记、状态、指派，五项缺一不可。
- [ ] 超期任务使用「红色 + alert 图标 + 「已超期」文字 + 加粗描边」四重表达，不依赖单一颜色可辨识。
- [ ] diff 双栏左「当前值」右「建议值」，变更行左侧 3px 强调条 + edit 图标 + 「已变更」文字；新增文本片段带下划实线，未变更行可折叠。
- [ ] 高风险任务且提交人=当前登录人时，「采纳并提交」与「驳回」均为禁用态，按钮下方常驻原因文案，且同时出现「指派第二审核人」入口。
- [ ] 工程师角色看不到「指派审核人」「导出审核记录」「标记超期升级」三个控件（DOM 中不存在）。
- [ ] 商务、法务进入时行动条整条不渲染，仅显示只读说明条；管理层/知识库/管理员/观察者直链进入显示 404 变体并说明所需权限。
- [ ] 理由校验按风险分级生效：低风险免填、中风险 ≥6 字、高风险与驳回 ≥10 字；不足时提交按钮禁用并给出计数提示，已填内容不清空。
- [ ] 批量采纳仅对低风险任务渲染复选框；「全选」跳过非低风险并提示跳过数量；二次确认弹窗列出全部条目且按钮含数量。
- [ ] 冲突待决任务在未裁决前不可采纳，裁决后两个来源值均可在时间线查到，未被采用值标「未采用」。
- [ ] 承诺类任务（BR-06）对工程师与投标经理禁用采纳，仅法务可提交，且系统不给出推荐措辞。
- [ ] 审核记录时间线覆盖创建、指派、评论、采纳、驳回、超期升级六类事件，显示操作人、角色、时间、理由；不可删除。
- [ ] 五种状态（加载/空/错误/无权限/长内容）均有对应布局与文案，空态分四种且每种带一个主行动。
- [ ] 快捷键 J/K/A/R/`/`/Esc 可用，焦点环 2px 可见，Tab 顺序与视觉一致。
- [ ] 并发冲突（他人已处理、目标版本过期）提示明确且提交按钮禁用，不产生静默失败。
- [ ] 页面底部常驻「演示数据，非真实企业信息」，全站无 emoji、无夸张营销表述，按钮文案统一为「采纳 / 驳回 / 指派」。
