## 1. 页面目标

### 1.1 解决的问题

中标之后，「为什么赢」通常只剩一句口头结论。本页把一次中标拆成三样可核对的东西：

1. **证据分级的赢因**：把散落在评分表、澄清纪要、谈判记录、履约数据里的说法，按「已证实 A / 可能 B / 待验证 C」三栏落到具体因素上，并强制区分「有直接证据」与「只有结果」；
2. **评分的机械对照**：评分因素表把「类别—因素—等级—证据条数—确认人」摊开，让评审会能追问「这条 8 分是哪一页」；项目没有正式评分表时，按 BR-13 把 A 级降级展示并挂出告警，避免"凭结果反推断因果"；
3. **承诺的兑现状态**：履约验证 Tab 用「承诺 / 目标 / 实际 / 偏差 / 状态」逐条核对，未达成项当场触发 BR-14 经验降级流程并要求填写复核说明，把「赢过」和「做得到」分开看。

本页不产出报价、不产出承诺、不自动定级。等级由人确认（F11 验收项、§9.1 分工边界）。

### 1.2 成功标准

| 编号 | 标准 | 判定方式 |
| --- | --- | --- |
| S-01 | 投标经理在中标后 2 周内完成一次复盘：4 个 Tab 均有内容，A/B 因素 100% 有证据来源 | 复盘完成率统计 |
| S-02 | 任一 A 级因素可在 2 次点击内看到证据条目与来源（评分表条目 / 页码 / 会议纪要） | 抽检 20 条因素 |
| S-03 | 无评分表项目（`rp-02`）不会出现 A 级因素：进入页面即见告警，因素表全部按 B 级展示 | 对照 BR-13 断言 |
| S-04 | 履约「未达成」记录必须带复核说明才能完成降级发起，且生成待审等级变更 | 对照 BR-14 / LR-07 |
| S-05 | C 级因素无法从本页进入任何结论载体（简报、入库经验、引用记录） | 对照 BR-12 断言 |

### 4.2 视觉层级

- 一级：左栏项目卡（当前项目 2px 强调色左边框 + `--bg-subtle` 底）；二级：Tab 条；三级：因素卡 / 表格行；四级：证据条目与元信息（12px `--ink-3`）。
- **形状即等级**：A 级卡 1px 实线边框；B 级卡 1px 双线（`border-style: double` 3px，等效视觉双线）；C 级卡 1px **虚线**边框 + 卡底斜纹 4% 灰。文字与图标同时标注「A 已证实 / B 可能 / C 待验证」，禁止只靠颜色。
- 信息密度：三栏每栏一屏可见 2 张因素卡全展开（卡高约 210），密度高于经验库；表格 40 行高、12px 次要信息。数字统一 `tabular-nums`。
- 圆角 0、无渐变、无装饰动效；投影仅用于抽屉与弹窗。

## 10. 真实场景内容

### 10.1 场景叙述一：投标经理在 T+10 天完成 UK 项目复盘

王琛（投标经理）在中标后第 10 天打开 `/retro/rp-02`。左栏卡片立刻显示两件事：`A0 B2 C1`，以及琥珀色的「无评分表」徽标。他没有先点因素，而是先到「履约验证」——`fr-04` 那一行是红的：承诺「延迟交付赔偿 ≤0.5%/周，上限 10%」，实际「赔付 6%」，偏差「触发赔付」，说明写着「海运延误 6 周，按 1%/周条款赔付 6%（上限 15%）」。他点「触发经验降级」，弹窗里系统已默认勾选 `exp-10`（履约保函与 LD 上限需在投标阶段锁定，当前 A 级），目标等级 B；他在复核说明里写「UK 项目实际按 1%/周、上限 15% 条款执行并赔付 6%，与投标阶段设定的 0.5%/周、上限 10% 不一致，原 A 级判断不成立，降为 B 并要求后续项目核对条款原文」。提交后生成 `lc-04` 待审，因为是他自己发起，审批按钮对他禁用——他把链接发给知识库管理员吴桐。

随后他切到「评分因素表」：顶部告警条明确写着「该项目无正式评分表，按 BR-13 全部因素最高按 B 级展示」。三条因素 `wf-07`（疑似因品牌业绩加分）、`wf-10`（并网仿真报告提前提交）、`wf-14`（运维按 5 年报价）都在 B/C 之间，`wf-07` 的证据只有「仅有投标文件，无评分表细项」，证据条数 1。他点页面头 primary「提交经验入库审核」，弹窗「提交前检查」逐条列出：本次将入库 2 条 B 级（`wf-10`、`wf-14`）、1 条 C 级（`wf-07`，仅进假设区，不随附任何结论）、A 级 0 条（本项目无评分表，A 级不可提交）。他确认提交，三条因素以草稿状态进入经验库，等待吴桐按 LR-02 审核是否维持 B/C。

### 10.2 场景叙述二：工程师把 CZ 复盘里的口径经验搬到新项目

李维（技术投标工程师）正在做 `p-01`（CZ-Morava 100MWh，25 MW/100 MWh），招标书要求「AC-AC 往返效率 ≥88%，含辅助功耗」。他从「相似项目匹配」的「参考复盘」链接进入 `/retro/rp-03?tab=factors&from=match&projectId=p-01`。因素表里 `wf-06`（循环寿命条件与招标完全对齐，A 级，证据 2 条）和 `wf-02`（AC-AC 口径效率数据完整，A 级）都在，他展开 `wf-02` 的证据二级面板，看到「评分表第 6 项：技术符合性满分」与「澄清纪要 C-03」，并点「定位原文」跳 `doc-07` 的 `p41-s2` 锚点核对原句。

回到本页，他注意到 `rp-03` 的竞对差距写着「竞对 A 只给 DC 侧 92%，被要求补充说明」。他点进「方案与商务」的竞对卡 →「查看档案」跳 `/library?competitor=c-a&from=rp-03`，确认竞对 A 的手册标称是「92%（DC-DC）」。整条路径没有出现「我们效率更高」这类结论句——因为 A 级只支持「口径完整能避免澄清降分」这一条可检验的陈述，而不是「效率领先」。

### 10.3 场景叙述三：法务复核未达成项

陈立（法务/合规）从中标复盘进入 `/retro/rp-02?tab=fulfilment&status=missed`。他只读：未达成行红色竖条 + 加粗 + 「未达成」三重编码，说明里写明赔付比例与上限。他看到行操作里**没有**「触发经验降级」按钮，页面底部有 12px 灰字「降级由投标经理或知识库管理员发起」。他复制行链接，附在研判与风险的合规意见里，要求后续项目在投标阶段锁定 LD 条款上限。这条链路保证「法务看得见风险，但不改动等级」。

## 11. 验收标准

- [ ] 左栏固定展示 4 个已中标项目，每卡含 A/B/C 因素计数（形状 + 图标 + 文字三重编码）与「有/无评分表」徽标，切换项目后右栏 Tab 保持。
- [ ] 四个 Tab 均可通过点击与快捷键 `1–4` 切换，Tab 状态写入 URL 且刷新后保持。
- [ ] 经验三栏按 A/B/C 分列，A 实线、B 双线、C 虚线；C 栏每卡有固定提示条且不存在任何结论型入口（BR-12）。
- [ ] 评分因素表包含「类别/因素/等级/证据条数/确认人」5 列（+操作列），支持等级、证据条数排序与 20 条分页。
- [ ] 进入 `rp-02` 时顶部出现无评分表告警条，全部因素按最高 B 级展示；等级编辑中目标 A 被禁用并说明「LR-02 / BR-13：无评分表不可升 A」；提交前检查弹窗标注「A 级 0 条可提交」。
- [ ] 方案与商务 Tab 同时展示配置、合同模式、竞对三卡与竞品/商务经验列表，商务角色看不到技术细项行。
- [ ] 履约验证 Tab 5 列齐全（承诺/目标/实际/偏差/状态），未达成行有三重编码，`fr-04` 可触发降级弹窗。
- [ ] 降级弹窗复核说明 <6 字时提交禁用；提交后生成待审等级变更，发起人无法审批本人变更（BR-08、LR-03、LR-04、LR-07）。
- [ ] 只读角色（商务、法务、管理层、观察者）页面上不存在任何写入型控件；`admin` 直链进入显示权限不足页且不泄露项目名。
- [ ] 所有缺失值显示 `—` 且 tooltip 为「原文未披露」，全页无 `0` 填充的缺失值（BR-02）。
- [ ] 加载、空、错误、无权限、长内容五类状态均有对应布局与文案，错误态保留已渲染数据（§8）。
- [ ] 页面底部常驻「演示数据，非真实企业信息」，全页无 emoji、无夸张营销表述。
- [ ] 1440×900 下三栏单栏 ≥240 无横向滚动；1280 下左栏收窄至 264、三栏 ≥208，仍无横向滚动。
- [ ] 每次写入产生 Toast 与审计事件，因素卡「最近变更」可追溯到人与时间（BR-09）。
