## 1. 页面目标

**要解决的问题.** 一名投标经理同时跟 3 个项目：p-01 CZ-Morava 25 MW / 100 MWh（截止 2026-11-08）、p-02 DE-Lahn 50 MW / 200 MWh（2026-11-25）、p-03 UK-Northgate 15 MW / 60 MWh（2026-10-30）。背后是 14 份文档、60 条参数实例、42 行对比、9 条审核任务、8 条风险、30 条审计事件，分散在 7 个项目内页里。每天开工前必须回答三问：**今天先做哪个项目**（截止 vs 门禁 vs 待办）、**哪个项目有废标级风险**（强制条款、承诺口径）、**哪些动作卡在人身上**（超期审核、待决冲突）。逐个页面点开才能拼出答案，这正是本页要消灭的成本。

**本页只做四件事**

1. 跨项目 4 个 KPI（在投项目 / 待我审核 / 高风险 / 情报条目），按角色与项目 ACL 计算，可下钻；
2. 「我的待办」，超期项在视觉上必须先于其他项；本页只做入口与优先级表达，审核动作在 `/reviews`；
3. 在投项目卡：规模、截止 T-n、五阶段门禁、资料完整性、风险数、判定摘要；
4. 风险分级与 Top3、最近 8 条审计活动，作为「今天态势」的横切面。

**不做**：参数编辑、结论生成、报告发布、竞对档案维护、批量确认。这些动作在各自页面完成，工作台只给带参数的入口，避免退化成第二套参数矩阵。

**成功标准**

| # | 标准 | 判定方式 |
| --- | --- | --- |
| S-01 | 30 秒内说出「今天先补 p-03 的资料缺口，再裁决 p-01 的效率口径」 | 可用性测试，10 人中 ≥8 人完成 |
| S-02 | 任一条待办从工作台到可操作位置 ≤ 2 次点击 | 点击计数 |
| S-03 | 超期项 100% 出现在首屏，且带形状区分（2px 危险描边 + 左侧 3px 竖条） | 视觉走查 |
| S-04 | KPI 数字与抽屉行数、明细页计数完全一致（差值 0） | 与 `/reviews`、`/insights` 对数 |
| S-05 | 跨项目零越权：KPI、项目卡、待办、风险、活动五处均按项目 ACL 过滤 | 8 角色逐个走查 |
| S-06 | 首屏可交互 ≤2 s（Mock 数据，本地），无整页 spinner | 手工计时 + Lighthouse |

## 2. 适用角色与权限

引用主 PRD 17.3：工作台对 8 个角色**全部可见**；**编辑**仅工程师与投标经理，其余 6 个角色为**只读**；没有「不可见」。因此本页的权限表达不落在整页拦截，而落在**控件不渲染**与**项目 ACL 过滤**两处。

三态落地：编辑 = 控件可用并写审计；只读 = **不渲染**写入控件，必要处给 12px 灰字说明；不可见 = 导航不出现，直链进 404 变体。

**谁看不到什么（与 17.3 一致性说明）**

1. 商务、法务、管理层、知识库管理员、系统管理员、只读观察者：页头**不渲染**「新建项目」。只读角色不给灰按钮、不给灰字提示，避免主行动歧义；新建入口在有权限角色的项目列表页完成。
2. 管理层、系统管理员：待办行不渲染「处理」，也不渲染跳 `/reviews` 的链接（审核待办对其不可见）；只显示任务类型、标题、项目名、状态。
3. 知识库管理员、系统管理员：项目卡「进入对比」、判定 chip、风险 Top3 链接一律不渲染（对比分析 / 研判与风险对其不可见），卡片只保留概览与资料入口。
4. 系统管理员：活动行的文档类目标不可点，灰字「系统管理员不可读取文档正文」；仅可见动作类型、对象标识、时间、IP、结果（F10 硬约束）。
5. 商务 / 法务 / 管理层 / 知识库管理员 / 系统管理员 / 只读观察者：本页不渲染任何「批量确认」「指派」「审批」「发布」按钮；该约束写进验收，防止后续迭代误加。
6. 只读观察者：顶部常驻提示条「当前为只读视角，写入操作不可用」；待办数按团队口径显示，个人视角为空。

**视觉层级**

1. 第一层：KPI 数字（28px 等宽 `tabular-nums`）+ 项目卡标题（16px）；数字是唯一允许用 28px 的元素。

3. 第三层：待办标题与风险 Top3 文本（13px，最多 2–3 行）。
4. 第四层：审计活动（12px，次要色 `--ink-3`），只作背景信息，不与待办抢注意力。
5. 全页仅 1 个实心 primary；圆角 0、1px 边框分层、无投影（抽屉与弹窗除外）；禁止渐变色块。
6. 信息密度：首屏承载 4 KPI + 3 项目卡 + 5 待办 + 3 风险 + 8 活动，共约 28 个信息块；不再增加第五个区块，新增需求走项目概览。

## 7. 交互细节

**7.1 筛选与排序**

- 项目卡排序：默认截止日升序（T 小在前）；可切「风险数降序」「完整性升序」，状态存 `?sort=risk|completeness`；排序控件为文字分段器，不用下拉。
- 活动筛选：「全部 / 仅业务操作（排除登录）/ 仅拒绝」三 chip，默认「全部」，`?audit=business|denied`。
- 待办排序：**固定**为「超期 → 高 → 中 → 低 → 截止日升序」，不提供改序。理由：待办顺序本身就是优先级结论，允许改序会让超期项被埋。
- 风险条形图：点击柱过滤 Top 列表为该等级，再点取消，`?risk=high`；筛选时柱体加 2px 实心描边。

**7.2 展开与抽屉**

- 项目卡不平铺折叠，全部信息一次给足；只有门禁 chip hover 200 ms 出 tooltip：`校验 · 已阻塞` + note「3 份竞对资料晚于计划到达，标准化未启动」。
