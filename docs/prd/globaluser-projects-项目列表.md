## 1. 页面目标

### 1.1 要解决的问题

海外大储投标窗口通常 2–4 周，技术投标工程师同时跟 2–3 个项目，投标经理同时看 3–5 个。工作台回答「今天该处理哪一件」，但回答不了「我手上到底有哪些标的、各自死线在哪、哪个已经带病」。项目列表要解决三件事：

1. **一眼扫全量**：3 个在建项目的国别、规模、阶段、死线、完整性、风险数在同一屏内可比，不需要逐个点进去；
2. **按病理切片**：法务只想看「高风险」，商务只想看「CZ/DE」，投标经理只想看「7 天内到期且完整性 <90%」，筛选必须能叠加且状态可回退；
3. **入口收敛**：新建项目是本模块唯一的创建入口，字段与校验必须在提交前拦住两类错误——**时长超过 8 h 的规模录错**、**截止日填到过去**（补录历史项目不属于本入口职责）。

### 1.2 成功标准

| 编号 | 标准 | 度量 |
| --- | --- | --- |
| S-01 | 从侧栏进入后 3 秒内能说出「最急的项目是哪个」 | 可用性测试 5 人，4/5 正确 |
| S-02 | 建项目 ≤3 步完成（单弹窗三组字段，无翻页），一次通过率 ≥90% | 表单埋点：提交次数 / 成功数 |
| S-03 | 规模与日期类错误 100% 在客户端拦截 | 提交前校验日志无漏网 |
| S-04 | 排序、筛选、视图切换在返回时保持 | URL query 可复制复现同一视图 |
| S-05 | 只读角色不出现任何写入控件 | 权限走查 8 角色 × 全控件 |

## 2. 适用角色与权限

### 2.1 矩阵引用

主 PRD 17.3 对本页的判定为：工程师 **编辑**、投标经理 **编辑**、商务 **只读**、法务 **只读**、管理层 **只读**、知识库管理员 **只读**、系统管理员 **编辑**、只读观察者 **只读**。本节把「编辑」拆成三个具体动作：`create`（新建项目）、`editMeta`（改项目基本信息）、`archive`（归档 = 软删除）。系统管理员的「编辑」按 17.3 第 3 条硬约束限定为**元数据层**，不含任何文档正文。

### 4.4 视觉层级与信息密度

- 层级从高到低：**项目名 > 截止日 > 风险 > 完整性 > 阶段 > 规模 > 成员**。项目名 14px/500 主色，其余 13px，辅助信息 12px `--ink-3`；
- 全页仅一个强调色（`--accent #1f4ed8`）用于主按钮、当前排序列箭头、选中 chip；风险红/琥珀/绿只用于状态，不用于装饰；
- 数字一律等宽 + `tabular-nums`，规模、完整性、风险计数三列纵向对齐，便于竖向扫读；
- 表格视图默认；卡片视图用于演示与快速浏览，信息量比表格少一列「阶段门禁」，不允许卡片承载表格没有的独有信息。

## 5. 数据与字段

### 5.1 数据来源

本期为前端 Mock（`mydemo/src/app/core/mock/projects.ts` 等）。接口形态约定为 `GET /api/projects?q=&country=&stage=&risk=&sort=&dir=&page=`，返回 `{ items: ProjectSummary[], total, facets }`；`facets` 提供各筛选项的计数（用于选项后括号数字），后端未就绪时前端按本地数据计算。风险数为派生值 `GET /api/projects/{id}/risk-summary`，与研判页同源。

### 5.2 字段清单

| 字段 | 来源 | 类型 | 示例 | 格式规范 |
| --- | --- | --- | --- | --- |
| `id` | 系统生成 | string | `p-01` | 编号递增 `p-01`…，不可改 |
| `name` | 用户录入 | string | `CZ-Morava 100MWh 独立储能` | 2–40 字；表格单行省略、卡片 2 行省略，`title` 全称 |
| `customer` | 用户录入 | string | `Morava Grid a.s.（虚构）` | ≤40 字；表格 24 字省略 |
| `country` | 用户选择 | enum | `CZ` | 6 值：DE/UK/IT/CZ/AU/PL；展示「捷克 CZ」双写 |
| `mw` | 用户录入 | number | `25` | 1 位小数，单位 `MW`，等宽右对齐 |
| `mwh` | 用户录入 | number | `100` | 1 位小数，单位 `MWh` |
| `durationH` | 派生 `mwh/mw` | number | `4.0` | 1 位小数 + `h`，只读，录入时实时跟随 |
| `route` | 用户选择 | enum | `LFP 液冷` | LFP 液冷 / LFP 风冷 / 钠离子 / 其他 |
| `stage` | 系统状态 | enum | `comparison` | 摄取/抽取/校验/对比/研判/已发布 六态 |
| `deadline` | 用户录入 | date | `2026-11-08` | `YYYY-MM-DD` + 右侧徽标 `T-15 天` |
| `completeness` | 派生 | number | `87` | 百分比整数 + `%`；未跑抽取时显示 `—` |
| `gateBlocked` | 派生 | bool|null | `true` | 存在阻塞门禁时在阶段后加「阻塞」文字 + alert 图标 |
| `riskHigh/mid/low` | 派生 | number | `3/2/1` | 无风险显示「无」；未生成时 `—` |
| `riskTotal` | 派生 | number | `6` | 排序次键 |
| `memberCount` | 派生 | number | `4` | 超过 4 人显示「4+」 |
| `competitorCount` | 派生 | number|null | `3` | 无资料时 `—`，不填 0 |

| `updatedAt` | 系统 | datetime | `2026-11-06T14:32` | 列表显示 `11-06 14:32` |

### 5.3 缺失值约定

完整性、风险数、竞对数量在「阶段未到」时一律显示 `—` 并附 tooltip「原文未披露 / 对比尚未生成」，**禁止填 0**（BR-02）。`—` 参与排序时行为：升序排在末尾、降序也排在末尾（不与 0 混排），表头 tooltip 说明。

### 5.4 新建项目弹窗字段与校验

| # | 字段 | 控件 | 必填 | 校验规则 | 错误文案 |
| --- | --- | --- | --- | --- | --- |
| 1 | 项目名称 | 输入框 | 是 | 2–40 字，去首尾空格后非空；同国别下重名给**警告**不阻断 | 「项目名称需 2–40 字」/「同国别已有同名项目，确认继续？」 |
| 2 | 客户名称 | 输入框 | 是 | 1–40 字 | 「请填写客户名称（业主或 EPC）」 |
| 3 | 国别 | 下拉 | 是 | 6 值：DE/UK/IT/CZ/AU/PL | 「请选择国别」 |
| 4 | 额定功率 MW | 数字输入 | 是 | `0 < MW ≤ 999`，最多 1 位小数；不接受 0、负数、科学计数法 | 「功率需大于 0，单位 MW」 |
| 5 | 额定能量 MWh | 数字输入 | 是 | `0 < MWh ≤ 7999`，最多 1 位小数；且 `MWh ≥ MW`（即时长 ≥1 h） | 「能量需大于 0，单位 MWh」/「MWh 不应小于 MW，请核对单位」 |
| 6 | 时长 | 只读 | — | 派生 `MWh ÷ MW`，1 位小数；**上限 8.0 h**，下限 0.5 h | 「时长 9.0 h 超过 8 h 上限。请核对 MWh 是否包含扩容段，或 MW 是否为并网点功率；确属长时储能请点「申请例外」」/「时长 0.4 h 低于 0.5 h 下限」 |
| 7 | 技术路线 | 下拉 | 是 | LFP 液冷 / LFP 风冷 / 钠离子 / 其他 | 「请选择技术路线」 |
| 8 | 客户类型 | 下拉 | 是 | 电网公司 / 市政公用事业 / 独立发电商 / 配电网公司 / EPC / 工商业业主 | 「请选择客户类型」 |
| 9 | 合同模式 | 下拉 | 是 | EPC 总承包 / 设备供货 + 调试 / 设备供货 / 运维服务 | 「请选择合同模式」 |
| 10 | 投标截止日 | 日期选择器 | 是 | `deadline ≥ 今天（2026-10-24）`；日历中过去日期置灰；手工输入越界阻断 | 「截止日不得早于今天（2026-10-24）」 |
| 11 | 初始成员 | 多选（人员） | 否 | 默认勾选当前登录人；至少 1 人可提交 | 「至少保留 1 名项目成员」 |
| 12 | 备注 | 多行文本 | 否 | ≤200 字，实时字数计数 | 「备注不超过 200 字」 |

校验时机：字段失焦即校验、输入过程中仅清错不报错；提交时全量校验并把焦点移到第一个错误字段；提交成功后字段值不保留，失败时全部保留。

## 6. 主次行动

**唯一 primary**：页头右侧「新建项目」（36h，`--accent` 实底）。它是本页唯一创建入口，全页只有它使用强调色实底。

**次行动（均为文本按钮或描边按钮）**

1. 「清空筛选」——仅在有筛选时出现，位于工具条最右；
2. 「清空全部」——chips 行右侧，与上者同义，两处只保留可见的那一个（有 chips 时显示 chips 行的）；
3. 卡片/表格切换（分段控件 88×28）；
4. 行尾「更多」菜单：编辑项目信息 / 复制为新项目 / 归档项目（按权限裁剪）；
5. 风险计数（行内链接）；
6. 成员计数（行内链接，跳概览锚点）；
7. 「导出当前视图 CSV」——放在「更多」之外的工具条溢出菜单，仅工程师与投标经理可见，导出内容为当前筛选与排序结果。

## 7. 交互细节

### 7.1 视图切换

分段控件两段：「卡片」「表格」，图标 + 文字，选中态 `--accent-weak` 底 + 1px `--accent` 边。切换写入 `?view=`，默认表格。切换不重新请求数据，不重置筛选与排序。键盘：`1` 切卡片、`2` 切表格（输入框聚焦时不生效）。

### 7.2 筛选

| 筛选项 | 控件 | 选项与计数 | 逻辑 |
| --- | --- | --- | --- |
| 关键词 | 搜索框 320 | 占位「项目名 / 客户 / 规模，如 100MWh」 | 300ms 防抖；匹配 name、customer、`${mwh}MWh`、`${mw}MW`、id；不区分大小写 |

- 已应用条件在 chips 行逐个成 chip（`国别: CZ ×`），点 `×` 移除单项；chips 行右侧「清空全部」；
- 筛选变更后 150ms 内出结果，结果数变化通过页头副标题更新（`aria-live=polite`，不弹 Toast）；
- 筛选状态全量进 URL，可复制分享；`?stage=active` 为工作台专用别名，等价于「非已发布」。

### 7.3 排序与 aria-sort

| 列 | 排序主键 | 次键 | 升序/降序含义 | 表头可排序 |
| --- | --- | --- | --- | --- |
| 项目 | `name` 的 `localeCompare('zh-Hans-CN')` | `id` | A→Z / Z→A | 是 |
| 规模 | `mwh` | `mw` | 小→大 / 大→小 | 是 |
| 阶段 | 不排序（阶段是流程位置，不是大小） | — | — | 否 |
| 截止日 | `deadline` | `id` | 最早在前 / 最晚在前 | 是 |
| 完整性 | `completeness` | `riskHigh` 降序 | 低→高 / 高→低 | 是 |
| 风险数 | `riskHigh` | `riskTotal` | 少→多 / 多→少 | 是 |
| 成员 | 不排序 | — | — | 否 |

实现约定：

1. `<th scope="col" aria-sort="ascending|descending|none">`，第三态用 `none`；同一列点击三段循环「升序 → 降序 → 取消（回默认）」；
2. 可排序表头内为 `<button>`，含 `aria-label="按截止日升序排列"` / `"降序排列"` / `"取消排序"`，视觉箭头为内联 SVG（stroke 1.5），**不只靠箭头颜色**表达方向；
3. 默认排序 `deadline asc`（最急的在前），与「一眼看出最急项目」的目标一致；
4. 风险数排序以高风险为主键，符合 BR-05「强制条款与高风险优先暴露」；不提供任何「竞争力排名」类排序（BR-04）；
5. 本期不支持多列排序与拖拽列宽，表头 tooltip 明确「当前按截止日升序，点第三次取消」；
6. 排序只改 URL `sort`/`dir`，不重置筛选。

### 7.4 新建项目弹窗（md 560，可扩 lg 880 双列）

分三组：**项目标识**（名称、客户、国别）、**规模与路线**（MW、MWh、时长、技术路线）、**投标信息**（客户类型、合同模式、截止日、初始成员、备注）。字段与校验见第 5.4 节表格；校验时机为「失焦即校验 + 提交全量校验」。

关键交互：

- **时长实时计算**：填 MW 与 MWh 后，时长字段立即显示 `4.0 h`（只读输入框，右侧灰字「= 100 MWh ÷ 25 MW」）；
- **8 h 上限**：当 `MWh ÷ MW > 8` 时字段转红、下方出现错误行，**提交按钮禁用**；错误文案「时长 9.0 h 超过 8 h 上限。请核对 MWh 是否包含扩容段，或 MW 是否为并网点功率；确属长时储能请点「申请例外」」。同一弹窗内提供「申请例外」文本链接，展开一行说明输入 + 提交后生成待审批记录；待审批项目在列表顶部独立分组「待审批 1」内显示，不参与排序与筛选（该项为设计补充，标注为【假设】）；
- **截止日**：日期选择器以「今天 2026-10-24」为最早可选，过去日期在日历中置灰；手工输入 `2026-10-20` 时错误行「截止日不得早于今天（2026-10-24）；补录历史项目请走归档项目流程」；
- 提交成功 → 弹窗关闭 → Toast「已创建项目 p-04，可在资料管理上传招标文件」+ 「打开项目」按钮 → 列表首位插入新行并高亮 1.2s；
- 提交失败 → 弹窗不关闭，顶部错误条 + 「重试」，已填内容 100% 保留；
- Esc 关闭；关闭时若有未保存内容，二次确认「放弃已填写内容？」（危险操作二次确认）；
- 焦点管理：打开时焦点落「项目名称」，关闭后焦点回到触发按钮。

## 12. 跳转关系

| 方向 | 页面 | 携带参数 | 双向闭合说明 |
| --- | --- | --- | --- |
| 入 | 工作台 `/dashboard` | `?view=card`、`?stage=active`、`?risk=high&sort=riskCount&dir=desc` | 工作台的「查看全部」「进行中项目」「高风险」三处均有明确入口；本页页头副标题不反向链回工作台，靠面包屑 |
| 入 | 顶栏全局检索 | `?q=<词>` | 检索结果分组「项目」跳本页并预填关键词，本页搜索框同步显示该词 |
| 入 | 404 `/404` | — | 404 有「返回项目列表」，本页不反向链接 404 |
| 出 | 项目概览 `/projects/{id}/overview` | — | 概览页面包屑「工作台 › {项目名}」中的「项目」回到本页，带原 query |
| 出 | 研判与风险 `/projects/{id}/insights` | `?risk=high&from=projects` | 研判页顶部有「返回项目列表」，保留 `risk=high` |
| 出 | 报告中心 `/projects/{id}/reports` | `?template=rp-exec` | 仅管理层可见该入口；报告中心面包屑回概览再回本页 |
| 出 | 中标复盘 `/retro` | `?projectId={id}` | 仅知识库可见；复盘页「关联投标项目」回链本页 `?q={项目名}` |
| 出 | 资料管理 `/projects/{id}/documents` | 由新建成功 Toast「打开项目」→ 概览 → 资料管理 | 新建后空项目在概览页显示「去上传资料」主行动 |
| 出 | 登录 `/login` | `?next=/projects` | 登录成功回跳，保留原 query |
| 出 | 系统管理 `/admin` | `?tab=audit&target={id}` | 归档成功 Toast 的追溯入口；系统管理审计页可按 target 反查项目编号 |
