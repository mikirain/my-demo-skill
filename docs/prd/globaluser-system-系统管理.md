## 1. 页面目标

### 1.1 解决的问题

海外大储投标的竞对标书属机密、报价属绝密（主 PRD D-06），系统的可信度不取决于抽取模型多聪明，而取决于三件事能否被外部审计回答：**谁能看什么、口径由谁定义、谁在何时改了什么**。本页是这三件事的唯一落点，也是 F10 的界面载体：

- 角色权限散落在口头约定与共享盘目录里，跨项目越权无法证明「拦住了」；
- 48 项参数字典的口径（RTE 边界、循环寿命条件）靠工程师记忆，同名不同义反复出现；
- 置信度分流阈值（0.85 / 0.60）写死在代码里，业务侧无法解释「为什么这条进了强制人工」；
- 审计日志只在 IT 侧可查，投标经理评审会上被问「谁改的」答不上。

### 1.2 成功标准

| 编号 | 成功标准 | 验证口径 | 目标 |
| --- | --- | --- | --- |
| S-01 | 越权可拦截、可举证 | 跨项目/跨角色访问被拒且产生 `result=denied` 审计 | 100% |
| S-02 | 敏感操作可追溯 | 权限、字典、阈值三类写入全部落审计且带变更说明 | 100% |
| S-03 | 口径可解释 | 任一参数实例的置信度档位能反查到阈值来源与生效时间 | 100% |
| S-04 | 密级底线 | 系统管理员在任意入口均无法打开文档正文 | 0 例外 |
| S-05 | 配置可回滚 | 权限矩阵与阈值配置支持「恢复默认」，回滚本身也留痕 | 100% |
| S-06 | 审计可离线交付 | 审计日志可导出 CSV（UTF-8 BOM），30 条导出 ≤3 秒 | 达标 |

> 本页不承担业务判断：权限矩阵只声明「谁能做什么」，不声明「谁的判断更对」；阈值只决定人机分流比例，不改变判定六态（主 PRD 7.3）。

### 2.3 三条硬约束在本页的落地

1. **只读角色不渲染写入控件**：bidManager 的审计 Tab 内没有任何按钮，仅表格与筛选；knowledge 的字典 Tab 无操作列，列宽回收分给「必带条件」。
2. **禁止自审**：权限矩阵与阈值配置的提交人与复核人必须不同人（BR-08 的横向应用），提交后状态为「待复核」，复核人在页面顶部提示条内处理；单人无法直接生效。
3. **管理员不可读正文**：矩阵中 `admin` 行的「查看文档与原文」被锁定为「禁止」且不可点改；若尝试通过直链 `/projects/p-01/documents/doc-03` 进入，返回 404 变体「该页面仅对项目成员开放」，并写入 `result=denied` 审计。

> **矩阵列数说明（假设）**：权限矩阵为「10 操作 × 6 角色」，6 列为可分配角色（工程师、投标经理、商务、法务、管理层、系统管理员）。知识库管理员与只读观察者属**预置视角**，能力由模板固定（knowledge＝字典只读 + 经验库编辑；viewer＝全站只读），不出现在可编辑列，避免被误配为可编辑。若后续需要配置，走 V2.0 的角色模板功能，本页不提供。

### 4.4 视觉层级

- 层级只有三层：页头（H1 24px）→ Tab 与卡标题（16px/600）→ 表格与正文（14px/13px）；不使用卡片阴影，仅 1px `--line` 边框。

## 7. 交互细节

### 7.1 Tab 与状态保持

- Tab 写入 URL：`/admin?tab=users｜dict｜thresholds｜audit`，刷新与后退保持；默认值按角色（见 3.1）。
- 切 Tab 保留各自筛选与分页（URL 附带 `q`、`dim`、`level`、`act`、`result`、`page`）；离开 `/admin` 再返回时保留最近一次 Tab 与筛选（globaluser 6.7）。
- 脏数据拦截：权限或阈值有未保存变更时切 Tab 或离开，弹二次确认「有未保存的变更，是否放弃？」；确定则丢弃并 Toast「已放弃变更」。

### 7.2 用户与权限

- **三态点击切换**：单元格点击循环 允许 → 只读 → 禁止 → 允许；`Shift + 点击` 反向循环；键盘 Tab 进入矩阵后方向键移动焦点，`Space` 切换，`Enter` 打开该格说明。
- **锁定格**：`admin × 查看文档与原文` 恒为禁止，格内锁图标，点击弹 420 弹窗：「系统管理员不可读取文档正文。该限制来自 F10 与 NFR-05，用于满足竞对标书机密级要求。如需核对文档内容，请转由项目成员处理。」弹窗仅一个「知道了」。
- **批量**：本页不设跨格批量填充（一次误填会同时放权 10 个操作），仅在矩阵左侧行头提供「整行设为禁止」并二次确认；列头提供「整列复制自…」下拉（复制自工程师/投标经理等），复制后仍需逐格确认生效范围提示。
- **保存**：顶部主按钮。提交前本地校验两条：① admin 行 `viewDoc` 必须为禁止；② 每个操作至少有 1 个角色为「允许」，否则提示「『发布结论/导出报告』全部角色均为禁止或只读，将无人可发布」，需显式勾选「知悉并继续」才能保存。保存后进入「待复核」，提示条出现；复核人（非提交人）通过后生效，审计写 `config` 类型。
- **恢复默认**：弹 md 560 二次确认，列出将被改动的格数（如「12 格将回到默认值」），确认后恢复为 5.3 表值并同样走复核。
- **变更说明**：必填，≥6 字（LR-03 的横向应用），计数实时显示 `12/200`。
- **用户表**：角色下拉改人即生效，弹确认「将 郑一 从 只读观察者 改为 商务/报价？其导航与写入能力立即变化」；停用用户需二次确认，停用后其历史审计保留。

### 7.3 参数字典

- **搜索**：按 key、中文名、别名三处模糊匹配，命中旁标来源（`key 命中` / `别名命中`）；`/` 聚焦搜索框；输入 `system rte` 可空格分词命中 `system_rte`。
- **维度 / 层级筛选**：维度为 6 个 chip（技术 12 / 性能 10 / 安全 7 / 质保 4 / 交付 6 / 商务 9，合计 48）；层级为二级下拉（cell 3 / module 1 / rack 2 / system 20 / plant 22，合计 48）。两维为 AND，例如「性能 × system」筛选后显示「48 项中的 7 项」。
- **排序**：默认 维度 → 层级(cell→plant) → key；可点列头切换 key / 中文名 / 版本 / 实例数升降序。
- **新增 / 编辑弹窗（lg 880，居中）**：左右两栏分组——左栏「标识」（key、中文名）与「版本与影响」（实例数、最近修改、状态），右栏「口径」（维度、层级、单位、必带条件 6 项复选：DoD / 温度 / SoH 末值 / 测量边界 / 负载率 / 统计周期）与「别名（0–8）」；两栏下方通栏「变更说明」（≥6 字，编辑时预填上次说明，计数 `18/200`）。弹窗底部固定操作条：取消 / 保存；`Esc` 关闭，焦点回到触发的行。
- **key 校验**（失焦即校验，错误就地显示在字段下方）：

| 校验项 | 规则 | 失败文案 |
| --- | --- | --- |
| 字符集 | `^[a-z][a-z0-9_]{2,39}$` | 「key 只能用小写字母、数字、下划线，且以字母开头，3–40 位」 |
| 唯一性 | 与现有 48 个 key 不重复（忽略大小写） | 「key `cycle_lifes` 已存在，请直接编辑该条目」 |
| 相似提示 | 与现有 key 编辑距离 ≤2 时给提示，不阻断 | 「与 `system_rte` 相似（编辑距离 2），确认要新建独立参数？」 |
| 别名冲突 | 新 key 的名称不得与既有别名相同 | 「`RTE` 已是 `system_rte` 的别名，请改为追加别名」 |
| 单位必填 | 无量纲必须显式选 `—` | 「无单位请选 `—`，不要留空」 |
| 条件必填约束 | 性能类 RTE/循环寿命必须勾选对应条件 | 「`system_rte` 必须勾选 边界、温度、负载率，否则不可参与比较」 |

- **别名管理**：输入框回车追加为 chip，上限 8 个；chip 右侧 x 删除；重复别名即时标红；保存前做全局唯一校验，冲突列出占用方（如「`System Efficiency` 被 `system_rte` 占用」）。删除别名不回溯历史已确认值，仅在 tooltip 说明「历史值仍按原别名可检索」。
- **停用**：实例数 > 0 时弹二次确认，列出受影响项目（如「18 个实例，涉及 p-01、p-02」），停用后抽取不再命中，历史实例标「字典已停用」。
- **编辑 key**：key 字段只读并给灰字「key 创建后不可修改，避免历史参数断链」。

### 7.4 阈值配置

- 五张卡：置信度路由（autoPass / manualForce）、抽检（sampleRate）、知识库有效期（kbValidityMonths）、审核超时（reviewTimeoutHours）、六维权重；最下方「变更说明」文本域 + 固定操作条。
- **实时校验**：`manualForce < autoPass`，违反时两字段同红并给文案「强制人工阈值 0.60 必须小于免检阈值 0.55」；权重右侧常显「合计 100」，不为 100 时数字变红 + 差额提示「差 -4」，主按钮禁用。
- **权重联动**：任一维改动后，其余维不变、合计实时更新；提供「按招标评分表归一」按钮打开 md 560，输入 6 个原始分值后按比例折算到 100（仅助手，不做黑箱改写，折算过程展示在弹窗内）。
- **数值步进**：阈值输入支持上下键 ±0.01，shift ±0.05；权重 ±1，shift ±5。
- **变更说明必填**：≥6 字，≤200 字；与上一次保存的说明做 diff 展示（新增文字下划线）。
- **保存**：校验通过 → 二次确认（列出 before → after 差异表）→ 进入「待复核」→ 复核通过后生效，Toast「阈值已保存，对新任务生效；历史判定不重算」。
- **恢复默认**：回到 5.5 默认值，弹窗内展示 6 项 before → after。
- 「查看生效结果」跳参数矩阵并按 `manualForce` 过滤。

### 7.5 审计日志

- **筛选**：动作（10 类多选）、操作人（8 人选）、结果（成功/拒绝）；顶部显示「30 条中的 3 条」，并提供「清空筛选」文字按钮。
- **排序**：默认时间倒序；可切操作人升序。分页 20/页。
- **行展开**：点击行展开 96px 详情区：完整摘要、权限快照（该角色当时的 10 操作三态，只读展示）、对象链接、UA、会话编号。

- **不可修改**：全表无编辑、无删除；行右键菜单只有「复制事件编号」与「复制链接」。
- **管理员边界**：对象为 `doc-*` 时只给「查看元数据」（文件名、页数、qualityScore、哈希、解析状态），不渲染「查看正文」。

## 10. 真实场景内容

### 10.1 场景一：评审前的审计核对（叙述）

孙黎 08:05 用系统管理员账号登录，落在「用户与权限」。她的习惯是先看审计，再看配置。切到「审计日志」，默认时间倒序，第一屏是昨夜 20 条：李维在 `pv-017 系统往返效率` 上把原文的 DC 侧效率按 AC-AC 口径重算（摘要里有理由，她点开看到「DC 侧 92.4%，按 D-11 内部口径折算为 AC-AC 88.5%，含辅助功耗 2.1%」），王琛通过了 `task-08 结论审核`，周敏导出了 `DE-Lahn 一页简报 v2.0`（脱敏模式，IP 10.20.31.9）。她按结果筛「拒绝」，只剩 1 条：`aud-030`，郑一（只读观察者）在 10-24 01:00 尝试导出「报价敏感字段」，被拒。她展开行，权限快照显示该账号 10 个操作全部为只读或禁止，`viewPrice = 禁止`——只读观察者按预置模板不参与写入与商务数据，没有异常。她把这一条复制链接发到合规群，评审会上作为「越权可举证」的例证。随后她切「阈值配置」，确认抽检比例仍是昨天改过的 15%，变更说明写着「低置信度区间近 30 条记录出现 7 个，10% 抽检覆盖不足，上调至 15%」，复核人王琛，10-23 16:50 生效。全程没有打开任何一份标书正文。

### 10.2 场景二：一条别名的两次驳回（叙述）

吴桐（知识库管理员）在竞对 C 的英文手册 P.22 看到 "System Efficiency"，想让系统认出这个词。她在 `/admin?tab=dict` 搜索 `system_rte`，看到已有 3 个别名：Round Trip Efficiency、RTE、System Efficiency——原来已经收录。她改而想新建独立参数 `system_efficiency`，理由是「对手把 DC-DC 效率也这么叫，口径不同」。点「新增参数」后，key 校验通过，但中文名输入「系统效率」时触发相似提示：「与 `system_rte` 相似（编辑距离 2），确认要新建独立参数？」；保存时又撞上别名冲突：「`System Efficiency` 已被 `system_rte` 占用」。系统没有让她绕过，而是给出两条路径：在 `system_rte` 上追加带边界的别名，或新建 `system_rte_dc`。她选了第一条，提交别名 `System Efficiency (DC-DC)`，状态进入「待复核」，说明写「竞对 C 手册 P.22 用该词指 DC-DC 边界，需与 AC-AC 区分，避免判为可比」。孙黎复核通过，字典版本 v4，审计新增一条 `config` 事件。整个过程她没有任何写权限被放宽——她提交的是**申请**，落地的是管理员的**复核**。
