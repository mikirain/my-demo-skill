## 1. 页面目标

**解决的问题**：投标团队每次拿到新的竞对标书，都要重新找「这家对手上次报的 RTE 是多少、质保怎么写的、哪个项目赢过」。这些信息散落在个人 Excel、旧版手册和上一标的压缩包里，导致三件事反复发生：同一参数口径被重复争论；引用了 2024 年的旧手册当现值；无法判断一条情报的来源是否可信。

本页把跨项目的竞对档案收敛为一个**可检索、带来源与日期、带时效治理**的只读情报库，回答四个问题：这家竞对属于哪个梯队、覆盖哪些区域、有几个在售型号；它公开承诺了哪些关键参数、每条来自哪份文件的第几页、距今多久；它参与过哪些项目、结果如何；这些情报现在还能不能直接用。

| 目标 | 对应 F9 关键输入 / 输出 | 成功标准（可度量） |
| --- | --- | --- |
| 情报可检索 | 输入：已发布版本的竞对确认值 | 从进入页面到定位某竞对某参数 ≤ 3 次操作（选竞对 → 输关键词 → 命中高亮） |
| 每条可溯源 | 输出：竞对档案、参数时间线 | 时间线 100% 条目带「来源文件 + 页码/章节 + 采集日期」；无来源条目占比 ≤ 1% 且必须显式标「无引用」 |
| 时效可治理 | 输出：过时标记、复用建议 | 距今 > 18 个月的条目 100% 标「超出有效期」，且不进入默认推荐、不被默认排序置顶 |
| 口径不被误用 | 输出：复用建议 | 跨竞对同名参数不排名、不算均值；只按时间倒序并列，附四要素（值/单位/条件/层级）差异说明 |

本页**不做**的事：不提供竞品资料爬取或抓取入口（PRD 2.5 本期不做）；不提供批量确认、批量引用（会绕过入库审核）；不推断对手报价成本与利润率（仅展示区间与结构，缺失即 `—`）。

## 2. 适用角色与权限

权限矩阵依据主 PRD **17.3**：竞品情报库一行对 8 个角色分别为「工程师 编辑 / 投标经理 编辑 / 商务 只读 / 法务 只读 / 管理层 只读 / 知识库管理员 编辑 / 系统管理员 只读 / 只读观察者 只读」——即**本页对 8 个角色全部可见，无「不可见」情形**。因此本页权限差异只体现在写入控件上，且当前 Demo 整体处于**只读演示态**。

### 2.2 三条硬约束在本页的落地

1. **只读角色不渲染写入控件**：商务、法务、管理层、系统管理员、只读观察者看到的页面里，`引用`/`入库`/`审核`/`补录` 按钮**不存在**，而不是禁用；若用户从外部文档按图索骥寻找，页面底部说明条给出灰字「发起入库需 知识库管理员 / 技术投标工程师 权限」，不弹窗、不引导申请。
2. **自审拦截**：知识库管理员对待审条目点「通过」时，若该条目的提交人是本人，按钮禁用并就地显示「BR-08：高风险写入不可由提交人自审，请转交另一名知识库管理员」。
3. **管理员不读正文**：系统管理员视角下，来源文件只能看到「文件名 + 页数 + 哈希前 8 位 + 解析状态」，点「查看来源文件」无入口。

## 5. 数据与字段

### 5.1 数据来源

| 来源 | 内容 | 边界 |
| --- | --- | --- |
| 企业库（跨项目，本页唯一数据源） | 已审核通过的竞对确认值、型号、参与项目记录 | 与「项目库」双库分离：项目库内为项目级参数实例（`pv-001`…），本页只读企业库，不回写项目库 |
| 项目库回流 | 项目内状态为「已确认 / 已修正」的竞对参数，经入库审核后进入企业库 | 未审核不进企业库；撤回保留痕迹（NFR-07） |
| 来源文件 | 官方产品手册、中标公示、项目内上传的竞对标书摘要、现场铭牌照片 | 仅合法来源，来源四档可靠性由上传人标注（D-02、D-05）；系统不提供爬取 |
| 阈值配置 | 知识库有效期（默认 18 个月） | 值来自系统管理 `kbValidityMonths=18`；改动影响全站时效判定 |

## 9. 规则引用

| 编号 | 规则要点（一句） | 本页落地表现 |
| --- | --- | --- |
| BR-01 | 数值必须可跳原文，无证据降权并标「无引用」 | 每条情报必须有「来源文件 + 采集日期」；缺来源的条目：值灰显（`--ink-3`）、加「无引用」灰徽标、`查看来源`禁用、不参与「复制档案摘要」默认范围（需勾选「包含无引用条目」） |

| BR-07 | 冲突不消解，多值全部保留 | 竞对 B 的 `system_rte` 两条值（89% 2026-06-02、87% 2024-05-11）并列展示，标「多值并存（2）」，不合并、不取新值覆盖旧值 |
| BR-08 | 双人规则：高风险项禁止编辑人自审 | 入库审核弹窗中，若当前审核人 = 提交人，「通过」禁用 + 就地说明；引用超期条目需二次确认（同源约束：高风险写入不由单人闭环） |
| BR-09 | 修正可审计 | 正式态补录页码、标记待复核、撤回入库均产生审计事件；卡片底部「最近变更」显示「11-06 14:32 吴桐 补录 lib-007 页码（原缺）」 |
| BR-10 | 置信度路由 | 铭牌照片经 OCR 未识别的值（置信度 <0.60）强制人工：显示「未识别」而非猜测值，条目状态为「待复核」 |
| BR-15 | 引用必须留痕 | 正式态引用写入后，条目「引用次数」+1，展开区显示「被 p-01 · cmp-012 引用 · 李维 · 11-06 14:32」 |

## 10. 真实场景内容

### 10.1 场景叙述一：口径仲裁前的 3 分钟摸底（李维 · 技术投标工程师）
