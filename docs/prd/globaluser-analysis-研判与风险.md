## 1. 页面目标

### 1.1 解决什么问题

对比分析页回答了「要什么、对手给什么、我们差在哪」，但没有回答评审会上真正被追问的那句「**所以呢**」。本页承担三件事：

1. **把矩阵读数变成可评审的判断**：每条判断必须是「结论 + 依据 + 类型」三段式，类型区分事实、推断、建议；推断一律以「待核实：」开头，不允许把推测写成事实。
2. **把风险从表格里提出来变成可交付的处置**：按高/中/低分组，每条带处置建议、责任人、状态，让法务与投标经理在评审前就能逐条销项。
3. **把不敢自动回答的问题留在明面上**：报价让利空间、承诺可用率由人填写，系统只给依据与授权提示，不生成数值。

同时本页是**研判阶段门禁**的执行点：已确认字段不足 15 项时拒绝生成草稿，并列出缺口清单与去向。

### 1.2 成功标准

| 编号 | 成功标准 | 度量口径 |
| --- | --- | --- |
| S-1 | 每条可被采纳的结论都有 ≥1 条可跳转证据 | 抽检 100% 命中原文档页码与片段（KPI-04） |
| S-2 | 无证据条目 100% 被拦截且计数可见 | 拦截数与列表条目数一致，采纳按钮不出现 |
| S-3 | 门禁不达标时生成按钮不可用且给出缺口去向 | 每个缺口项均可一键跳到参数矩阵对应筛选 |
| S-4 | 决策留白区的两个数值在本页零自动写入 | 审计日志中两字段全部 `correct` 类人工动作，无系统写入 |
| S-5 | 评审前 8 条高风险/中风险全部有责任人与状态 | 风险 Tab 中 owner 为空或 state=open 的条目数 = 0 |
| S-6 | 澄清清单可直接粘贴进答疑函 | 复制文本含问题、背景、影响、依据页码四要素 |

### 1.3 不做的事

- 不生成报价、不让利、不承诺可用率、不给 Go/No-Go 结论（BR-06）；
- 不对竞对做排名或打总分（BR-04）；不推断对手利润率；
- 不在本页审批结论（审批在 `/projects/[projectId]/reviews`）；不发布报告（`/reports`）。

### 2.3 三条硬约束的落地

1. `knowledge` / `admin` 直链 `/projects/p-01/insights` → 渲染 404 页变体「无访问权限」，说明「研判与风险仅对项目成员中的技术、商务、法务、管理层开放；如需查看请联系项目投标经理王琛」，并给出「返回项目概览」按钮；不显示任何条目计数，避免泄漏结论条数。
2. 高风险结论的采纳人与审核人不得为同一人：若某条高风险结论由李维编辑，则李维看到的「提交研判至审核」为禁用态，提示「BR-08 双人规则：高风险结论需由他人审核」。
3. 法务看不到结论的采纳/修改/删除按钮，也看不到决策留白输入框；法务只能改风险状态与处置意见，页面对法务显示一行说明「法务视角：仅风险确认可写」。

### 4.4 视觉层级与信息密度

- **第一层（一眼）**：门禁是否达标 + 主按钮能否点。门禁条用 1px 下边框与外发光区分，吸顶不遮 Tab。
- **第二层（十秒）**：Tab 计数与「已拦截」红徽标；结论卡片左强调边用形状区分类型（事实=实线 3px、推断=双线 3px、建议=虚线 3px），与 A/B/C 证据等级同一套形状语汇。
- **第三层（逐条）**：结论正文 14/1.5，依据 13，第三段元数据 12 用 `--ink-3`；数字一律等宽 + `tabular-nums`。
- 密度：一屏（900 高，扣除 240 顶栏/门禁/Tab）可完整看到 3 张结论卡片或 6 行风险；不放大留白、不用装饰图。

### 5.6 格式规范

- 效率与可用率保留 1 位小数并**必带边界或周期**：`88.5%（AC-AC）`、`99%（月度）`；无边界一律标「条件未标注」；
- 页码 `P.37`；参数 `pv-014`；对比行 `cmp-003`；结论 `ins-001`；风险 `risk-03`；澄清 `clr-01`；
- 缺失值一律 `—` 并附 tooltip「原文未披露」，**禁止填 0**（BR-02）；
- 时间 `11-06 14:32`；日期 `2026-11-08`；截止 `T-15 天`；
- 金额只出现区间与结构，不出现对手利润率推算。

## 7. 交互细节

### 7.1 Tab 与筛选

- 三 Tab 保持在 URL：`?tab=insights|risks|clarifications`，刷新与返回不丢；
- Tab 标题右侧计数为当前筛选后条数，未筛选时显示全量；「已拦截 2」为独立红徽标，只在结论 Tab 出现；
- 结论筛选：类型（全部/事实/推断/建议）、状态（全部/草稿/已采纳/已修改/已驳回/已拦截）、关键词（匹配正文与证据片段）；
- 风险筛选：级别、类别、状态、责任人；支持 `?level=high&owner=u-04` 直入；
- 澄清筛选：状态（未发出/已复制/已发出）；
- 筛选变化不重置滚动位置之外的状态；空结果给「清空筛选」主行动。

### 7.2 排序与展开

| 对象 | 默认排序 | 可切换 | 展开行为 |
| --- | --- | --- | --- |
| 结论卡片 | 类型序（事实→推断→建议）再按编号 | 最近修改 / 证据数降序 | 卡片默认显示全部三段；依据 >3 条折叠为「还有 2 条依据」 |

| 澄清表 | 编号升序 | 状态 / 影响维度 | 行展开显示背景与依据片段 |

## 9. 规则引用

| 规则 | 在本页的落地表现 |
| --- | --- |
| BR-01 证据优先 | 每条结论必须有可跳转依据；无依据 → 状态 `blocked`，采纳按钮不渲染，「已拦截」计数 +1；依据链接直达 `/documents/[docId]?page=…&anchor=…` 并高亮片段 |
| BR-02 缺失不等于零 | 关联对比行、关联参数、责任人、期限为空一律显示 `—` + tooltip「原文未披露」；决策留白未填显示「待填写」，不填 0 |
| BR-03 未披露不等于不具备 | ins-003「竞对 A 未披露可用率」不得作为劣势结论；此类条目只允许「转为澄清」或删除，卡片下方常驻提示「未披露不作为劣势统计」 |
| BR-04 不可比不排名 | 结论中禁止出现「第 1」「优于 A 但劣于 B」等排名表述；若草稿含排名词，保存时阻断并提示「不可比项不得排名（cmp-007 为不可比）」 |
| BR-05 强制条款置顶 | 强制条款非 compliant 的风险条目「来源」标 `cmp-0xx 强制条款` 并固定排在风险组首列，不可拖拽调序 |
| BR-06 决策留白 | 右栏两字段默认空；系统只给依据（招标 ≥98%/年、我方 98.5%）与授权提示，无预填、无建议值；文本常驻「系统不生成报价与承诺值」 |
| BR-07 冲突不消解 | 冲突待决字段不参与生成，门禁条显式标「冲突未决 3 条（不参与生成）」；点击可跳参数矩阵 `?status=conflict` |

### 10.4 用户会怎么用（三）：评审会前 40 分钟

王琛（投标经理）在评审会前一天下午打开页面。门禁条显示「结论草稿：可生成；提交审核：阻断 · 高风险 3 条未确认」。他先切到风险 Tab，把 risk-02 指派给李维、risk-03 指派给陈立，自己接 risk-01；三条高风险都在 20 分钟内从「待处理」转「处置中」。回到右栏，他填报价让利空间 3.5%、依据「竞对 A 预付 30% 高于我方 20%，以账期让利替代降价」，系统提示「在授权内」；再填承诺可用率 98.5%，依据「我方年可用率 98.5%，时间加权」，系统不再报错。此时子门禁转为通过，「提交研判至审核」由灰转蓝。他全选 5 条澄清复制成纯文本，粘进答疑函草稿，最后提交审核——页面跳转 `/reviews?source=insight&ins=ins-001,ins-002,ins-004…`，Toast「已提交 8 条结论至审核」。

### 10.5 门禁阻断的另一例（p-03）

UK-Northgate 60MWh 项目处于抽取阶段，已确认 9/60，3 份竞对资料晚到导致标准化未启动。进入本页时门禁条显示「已确认字段 9/60（需 ≥15）」，生成按钮灰显，下方缺口表列出：待复核 4 项、无引用 5 项、冲突待决 0 项，每项右侧「去参数矩阵」；页面不渲染任何结论卡片，只显示空态说明。这条路径确保「资料不全时不会产出一份看起来完整的研判」——这是团队在历史项目上踩过的最贵的坑。

- [ ] 拦截条目上不出现「采纳」按钮，只出现「补引用 / 转为澄清 / 删除」；
- [ ] 结论卡片完整呈现三段式（结论 / 依据 / 类型），依据可点击跳原文并定位到页码与高亮片段；

- [ ] 采纳、修改、删除、状态变更、决策留白保存各产生一条审计事件，页头「最近变更」可见；
- [ ] 风险按高/中/低分组，组头含条数与状态分布；每条有处置建议、责任人、状态三列；
- [ ] 风险置「已关闭」须填理由并二次确认；非投标经理角色该选项禁用且给出原因；
