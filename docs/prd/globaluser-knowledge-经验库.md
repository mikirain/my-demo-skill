## 1. 页面目标

### 1.1 解决什么问题

中标复盘产出的经验，如果只停在一份 PPT 或某个人的电脑里，下一次投标仍然从零开始。经验库要解决三个具体问题：

1. **可检索**：把「四类资产」变成能按类别、等级、状态、国别筛出来的条目，而不是一篇长文；
2. **可判断适用性**：每条经验必须写清「在什么条件下成立、在什么条件下不成立」，让下一个项目的人能自己判断能不能借；
3. **等级可信**：A/B/C 不能由写的人自己说了算，必须有证据、有复核人、有变更审批记录，防止把 C 级假设当 A 级结论复用（主 PRD 风险 R-14）。

一句话职责：**让「这一标为什么赢」成为带等级、带边界、带审批痕迹、可被下一个项目引用的组织资产。**

### 1.2 成功标准

| 编号 | 成功标准 | 口径 |
| --- | --- | --- |
| S-01 | 12 条经验全部可被四类 Tab 正确归类且计数一致 | Tab 计数之和 = 总数 = 12 |
| S-02 | 任一经验在 2 次点击内看到 12 个必填字段与证据来源 | 列表 → 抽屉 → 详情 Tab |
| S-03 | 缺字段的条目无法入库，且系统点名缺哪一项 | 入库按钮禁用 + 缺失清单 |
| S-04 | 等级变更 100% 留痕（申请人、时间、理由、证据、审批人、审批意见） | LR-08 |
| S-05 | 无一条变更由发起人自己审批通过 | LR-04、BR-08 |
| S-06 | 每一条经验可回答「被谁在哪个项目引用过」 | BR-15 引用留痕 |

### 2.3 三条硬约束在本页的体现

1. **只读角色不渲染写入控件**：商务登录后，表格「操作」列只剩「查看详情」，行尾不出现任何图标按钮；抽屉内「等级与变更」子 Tab 只渲染历史记录，不渲染「申请变更」区块。
2. **自审拦截**：`lc-01` 由吴桐（知识库管理员）发起，吴桐登录后打开该条，审批按钮**置灰并显示**「LR-04：不可审批本人发起的变更」——此处允许置灰而非隐藏，因为需要让用户知道为什么做不了（与只读角色的「不渲染」规则区分）。
3. **系统管理员不可读正文**：`admin` 在抽屉里看到证据来源条目（`正式评分表第 6 项`）但不渲染跳转按钮，鼠标悬停提示「系统管理员无原文查看权限」。

### 4.3 视觉层级与信息密度

- **第一层**：6 个统计卡（等宽、数字 24px 等宽字体 + `tabular-nums`），回答「这批资产有多少、可信度如何」；
- **第二层**：四类 Tab 与计数，回答「我要找的是哪一类」；
- **第三层**：表格，回答「具体是哪一条」。行内以**等级徽标**与**状态徽标**作为视觉锚点，标题为黑色 14px，其余列降为 `--ink-2`；
- **密度**：单屏（1440×900）可完整看到 12 行表格；统计卡不使用大数字堆叠，扣掉装饰，只留数字 + 标签 + 一个筛选热区；
- **等级形状**：A = 3px 实线左边框 + 实心绿点；B = 3px 双线左边框（`border-left-style: double`）+ 蓝点；C = 3px 虚线左边框 + 灰点。**形状在三米外也能区分 A/B/C**，不只依赖颜色。

### 5.4 缺失值规范

- 任何字段未取到 → 显示 `—`，悬停 tooltip「原文未披露」，**禁止填 0 或「无」**（BR-02）；
- 抽屉顶部显示入库校验条：`入库校验 11/12 · 缺：复核日期`，入库按钮禁用（见 7.6）；

## 7. 交互细节

### 7.1 筛选与 URL 状态

- 全部筛选写入 URL：`/experience?tab=deviation&level=A&state=draft&country=CZ&q=循环寿命&page=1&sort=reviewedAt:desc`；
- 搜索框 300ms 防抖，匹配 `title / summary / requirement / strategy`，命中片段在抽屉内高亮（`--accent-weak` 底）；
- 统计卡可点：点「A 6」→ 追加 `level=A`，点「待复核 2」→ `state=draft`，再次点击取消；
- 「清空」按钮在任一筛选生效时出现，清空后回到 `tab=competitor`（不重置 Tab，避免用户丢失上下文）；
- 筛选组合为空结果时**不自动放宽条件**，只显示空态（见 8.2）。

### 7.2 排序

| 排序项 | 默认 | 说明 |
| --- | --- | --- |
| 复核日期 | 降序（默认） | 同日期按等级 A→C 二次排序 |
| 等级 | A→C | 同级按日期降序 |
| 标题 | 拼音升序 | 少用，供导出前对齐 |

点击表头切换升降序，箭头图标 12px，三态（无 / 升 / 降）。

### 7.3 Tab 切换

- 四 Tab 切换**不整页刷新**，仅重查表格；Tab 计数实时反映当前其他筛选下的分布（即「等级=A 时，各 Tab 的 A 级条数」）；
- Tab 支持键盘 `←/→` 切换，`aria-selected` 同步；
- Tab 记忆：从抽屉关闭返回时保持原 Tab；从 Toast「查看」进入时按参数指定的 Tab 覆盖。

### 7.4 表格行

- 行 hover：底色 `--bg-subtle`，行尾出现「详情」文本按钮（无 hover 时也保留，保证键盘可达）；
- C 级行：整行左内边距 8px 处显示虚线竖条，且「等级」列后附灰字「仅假设区可用」（BR-12）；
- 待审变更的行：状态列右侧追加一个小徽标「变更待审 lc-01」，点徽标直接打开审批浮层；
- 行双击 = 打开抽屉，等同「详情」。

### 7.5 详情抽屉（520）

结构：头部（标题 + 等级 + 状态 + 关闭）→ 三个子 Tab → 底部动作区。

| 子 Tab | 内容 |
| --- | --- |
| 详情 | 12 字段（缺项以 `—` + 「原文未披露」呈现，且标红左侧 2px 提示条）；顶部入库校验条 |
| 等级与变更 | 当前等级 + 证据强度说明；待审变更卡（发起人/时间/理由/新增证据）；变更历史时间线（lc-01…）；「申请等级变更」入口 |
| 引用记录 | 表格：引用方项目 / 引用人 / 引用时间 / 用于何处（页面 + 行号）/ 引用时等级快照 |

抽屉交互：Esc 关闭、遮罩点击关闭、焦点回到触发行；抽屉内滚动独立，页头保持可见。

### 7.6 等级变更申请弹窗（md 560）

字段：

| 字段 | 控件 | 校验（对应规则） |
| --- | --- | --- |
| 当前等级 | 只读文本 | 展示 `B`，不可改 |
| 目标等级 | 三段单选 A / B / C | 不得等于当前等级；升到 A 且项目 `hasScoreSheet=false` → 选项禁用 + 原因「BR-13：该项目无正式评分表，最高只能评 B」（LR-02） |
| 新增证据 | 多行输入 + 「从资料中选」 | 升级（C→B、B→A、C→A）至少 1 条，为空则报错「LR-01：升级必须新增至少一条证据来源」；降级可为空（LR-07） |
| 变更理由 | 多行文本 200 字 | ≥6 字，否则报错「LR-03：变更理由至少 6 个字并写入审计」；降级时提示「LR-07：降级须写明原因」 |
| 提交 | 主按钮 | 若该条已有待审变更 → 提交按钮禁用 + 「LR-05：该条已有待审变更 lc-02，需先处理」 |

提交成功：Toast「变更申请已提交，等待审批（lc-04）」+ 审计事件 `aud-0xx`；条目状态不变，仅追加「变更待审」徽标。

### 7.7 审批（md 560）

- 打开方式：待审徽标、`?change=lc-01`、工作台待办深链；
- 内容：变更前后对比（`C → B`）、理由全文、新增证据列表（可点开原文）、发起人 + 时间；
- 操作：「通过」「驳回」+ 审批意见（驳回时意见必填，≥6 字）；
- **双人规则**：`requestedBy === 当前用户` → 两个按钮均置灰，上方黄条「LR-04：不可审批本人发起的变更。可由王琛（投标经理）审批」；
- 通过后：等级即时更新、证据来源追加到 `evidenceSources`、状态置「已核验」（LR-06）；若条目为「已停用」，状态**保持不变**（LR-06 后半句），Toast 明确说明；
- 驳回后：等级不变，历史追加一条 `rejected`，`reviewNote` 必填。

### 7.8 Toast 与危险操作

| 场景 | 文案 | 类型 |
| --- | --- | --- |
| 入库成功 | 「exp-05 已入库，状态：已核验」 | 成功 |
| 入库校验失败 | 「入库校验未通过：缺少 复核日期」 | 错误 |
| 变更提交 | 「变更申请已提交，等待审批（lc-04）」 | 成功 |
| 审批通过 | 「已通过：exp-04 等级 B → A，证据来源已追加 1 条」 | 成功 |
| 审批驳回 | 「已驳回，意见已写入变更历史」 | 中性 |
| 自审拦截 | 「不可审批本人发起的变更（LR-04）」 | 警告 |
| 导出完成 | 「引用清单已导出（CSV，12 条）」 | 成功 |

危险操作（停用、批量导出）：二次确认弹窗，按钮文案为动词短语（「确认停用」），禁止只写「确定」。

### 7.9 批量与快捷键

- 批量：勾选行后底部出现操作条「已选 3 条 · 导出引用清单 · 取消」，**不提供批量改等级**；

## 8. 状态覆盖

### 8.1 加载

- 统计条：6 个 88px 灰块（`--bg-subtle`，无动画闪烁）；
- 表格：8 行骨架，每行 40px，列宽与实际一致，中间两列留短灰条模拟文本长度差异；
- 不使用整页 spinner；超过 8 秒在表头下方出现一行「加载较慢，可稍后重试」灰字。

### 8.2 空

| 空态类型 | 图标 | 文案 | 主行动 |
| --- | --- | --- | --- |
| 全库为空（0 条） | 文件夹 | 「经验库还没有条目。中标复盘完成后可一键入库。」 | 「去中标复盘」→ `/retro` |
| 当前 Tab 为空 | 分类 | 「「商务与交付」暂无经验条目。」 | 「查看全部类别」 |
| 筛选无结果 | 放大镜 | 「当前筛选下没有经验条目：等级 A + 国家 CZ + 待复核。」 | 「清空筛选」 |
| 引用记录为空 | 链接 | 「这条经验还没有被任何项目引用。」 | 「去相似项目匹配」→ `/match` |
| 变更历史为空 | 时间线 | 「暂无等级变更记录。」 | 无（不给按钮） |

> 空态必须**点名当前筛选条件**，不用「暂无数据」这类无信息文案。

### 8.3 错误

- 就地错误条（表格上方 40px）：`经验库数据加载失败（ERR-KB-500）。已保留上次加载的 12 条。` + 「重试」；
- 单条数据异常（如等级值为空）：该行整行浅红底 + 「字段缺失，待修复」，仍可点开详情，但入库/审批按钮禁用；
- 审批提交失败：不关闭弹窗，弹窗内顶部红条 + 保留已填内容 + 「重试提交」；
- 写操作一律不得静默失败（全局约定 3）。

### 8.4 无权限

| 场景 | 表现 |
| --- | --- |
| 只读角色直链 | 正常渲染页面，全部写控件不渲染；页头右侧仅「导出」不出现 |
| 无页面权限角色（如有） | 404 页变体：「当前角色无权访问经验库。需要 知识库管理员 或 投标经理 权限。」+ 「返回工作台」 |
| 自审拦截 | 按钮置灰 + 黄条说明（见 7.7） |
| admin 点证据 | 链接渲染为纯文本 + 「无正文明细权限」 |

### 8.5 长内容

- 标题 > 40 字：列表单行省略，`title` 属性给全文；抽屉内换行不截断；
- 摘要 > 120 字：列表不展示摘要，抽屉内默认折叠 3 行 + 「展开全文」；
- 证据来源 > 5 条：抽屉内滚动区（最大 240px），底部显示「共 7 条」；
- 适用范围长文本：默认展示前 2 行，超出给「展开」（含「不适用」从句时必须展开，因为那是判断依据）；
- 变更历史 > 10 条：时间线分页「加载更早的变更」。

## 9. 规则引用

| 规则 | 本页落地表现 |
| --- | --- |
| **BR-01 证据优先** | 每条经验必须有证据来源；证据条目可点开原文页并高亮（`?page=37&anchor=pv-045`）；无证据来源的条目在列表「等级」列后显示灰字「无引用」，且不可入库 |
| **BR-02 缺失不等于零** | 12 字段任一缺失显示 `—` + 「原文未披露」；导出 CSV 中该单元格为空字符串，不写 0 |
| **BR-08 双人规则** | 审批按钮对发起人置灰（LR-04）；同一人不能既发起又通过，前端拦截 + 审计记录 |
| **BR-09 修正可审计** | 任何字段修改产生审计事件（原值/新值/人/时间/理由/版本），页脚「查看本条审计」可达 |
| **BR-11 经验必须带证据等级与来源** | 12 字段校验的核心两条；缺失时入库按钮禁用并点名 |
| **BR-12 C 级只能出现在待验证假设区** | C 级行整行虚线竖条 + 「仅假设区可用」；C 级条目在 `/match` 只进「待验证假设」区，本页不提供「作为结论引用」的入口 |
| **BR-13 无正式评分表最高 B 级** | 目标等级选 A 且源项目 `hasScoreSheet=false` 时，A 选项禁用并给出原因（exp-07 即此例） |
| **BR-14 履约未达成自动降级** | `fr-04`（UK LD 赔付 6%）转 `missed` 时，系统对 `exp-10` 写入一条降级申请（B → C），并置「待复核」；不直接改等级，仍需审批 |
| **BR-15 引用留痕** | 每次引用写一条记录：谁、何时、哪条、用于何处；引用时等级快照入档，事后降级不篡改历史引用 |
| **LR-01 升级必须新增证据** | 申请弹窗中升级时「新增证据」为空即报错；降级不强制 |
| **LR-02 升 A 需直接证据 + 有评分表** | 两条件分别校验：缺直接证据报「需直接证据（评分表/业主书面认可）」；无评分表按 BR-13 禁用选项 |
| **LR-03 理由 ≥6 字并入审计** | 输入框实时计数 `0/200`，< 6 字提交按钮禁用并给计数提示 |
| **LR-04 不可审批本人发起** | 审批按钮置灰 + 黄条（见 7.7） |
| **LR-05 单条仅一个待审变更** | 已有 `pending` 时申请按钮禁用并指向现有变更编号 |
| **LR-06 通过后追加证据并置已核验** | 通过动作三件事：改等级、追加证据、置 `verified`；若为 `deprecated` 则只改等级不动状态，Toast 说明 |
| **LR-07 降级可不附证据但须写原因** | 目标等级低于当前时，「新增证据」标为选填，理由标为必填并加提示 |
| **LR-08 全部变更进历史** | 「等级与变更」子 Tab 时间线包含：发起人、时间、理由、证据、审批人、审批意见、结果 |

## 10. 真实场景内容

### 10.1 场景 A：一条完整的 A 级经验（exp-01）

知识库管理员吴桐在评审前抽查 A 级条目，打开「竞对 A 的效率标称口径与报价边界」：

| 字段 | 内容 |
| --- | --- |
| 类别 | 竞品策略 |
| 源项目 | rp-01 DE-Lahn 200MWh 电网侧储能（2024 中标） |
| 适用条件 | DE · 100–300MWh · 市政公用事业 · 公开招标（两阶段） |
| 产品型号 | Aster 5000 |
| 招标要求 | AC-AC 往返效率 ≥88%，含辅助功耗（招标文件 P.37） |
| 我方策略 | 双口径披露（AC-AC 88.5% / DC-DC 91.2%）+ 答疑阶段推动统一测量边界 |
| 结果 | 中标，技术符合性满分 |
| 证据等级 | A（实线） |
| 证据来源 | ① 正式评分表第 6 项（AC-AC 口径加分）② 澄清纪要 C-03（业主确认统一为 AC-AC 含辅助） |
| 适用范围 | 适用于欧洲公开招标、业主对效率口径敏感的项目；**不适用**于仅比总价的框架采购 |
| 复核人 / 日期 | 李维 / 2026-08-14 |

用户在抽屉里点「澄清纪要 C-03」，跳到原文查看 `P.12`，正文对应段落高亮。整个过程不超过 3 次点击，这就是本页存在的意义：**A 级不是一个人说 A 就 A，而是能当场翻到那一页。**

### 10.2 场景 B：一条 C 级待复核条目（exp-03）与它的升级申请（lc-01）

「竞对 C 的低价 + 短交期组合（待验证）」是 C 级、状态「待复核」。表格里它左侧有一条虚线竖条，等级列显示「C 待验证」，附灰字「仅假设区可用」。

吴桐拿到竞对 C 在波兰项目的澄清文件后，点「申请等级变更」：

| 弹窗字段 | 填写值 |
| --- | --- |
| 当前等级 | C |
| 目标等级 | B（A 不可选：源项目 rp-03 有正式评分表，但本条无直接证据指向评分项） |
| 新增证据 | 竞对 C 澄清文件 2025-11-04（P.9：交期 20 周不含海运）；波兰项目答疑纪要 P.12 |
| 变更理由 | 「取得澄清文件，确认其 20 周交期不含海运，属多项材料共同支持」 |
| 结果 | 提交成功 → Toast「变更申请已提交，等待审批（lc-01）」 |

此时该条状态仍为「待复核」，行内追加徽标「变更待审 lc-01」。**等级不因申请而改变**——这是本页最容易出错的地方，也是验收必查项。

### 10.3 场景 C：双人规则拦截（lc-01 自审）

吴桐是 lc-01 的发起人。她打开审批弹窗想直接通过，两个按钮均置灰，上方黄条：

> LR-04：不可审批本人发起的变更。可由 王琛（投标经理）审批。

吴桐切换到王琛视角（顶栏「切换角色」）后，按钮可用。王琛看到变更对比 `C → B`、理由全文、两条新增证据，点「通过」并填审批意见「证据为对手澄清文件，属多项材料支持，同意升 B」。Toast：「已通过：exp-03 等级 C → B，证据来源已追加 2 条」。该条状态变为「已核验」，变更历史新增一条 `approved`。

### 10.4 场景 D：LR-02 / BR-13 拦截（exp-07 想升 A）

「并网仿真报告提前提交可缩短评审（待验证）」源项目为 rp-02 UK-Northgate 100MWh，该项目**无正式评分表**（BR-13 的演示条目）。

工程师李维试图把它从 C 升 A。打开弹窗后，「A」选项直接禁用，右侧灰字：

> BR-13：该项目无正式评分表，经验最高只能评 B 级。

李维改选 B，新增证据填「业主项目经理访谈记录 2026-10-18」，理由「获业主项目经理确认并网报告缩短评审周期，但无书面评分证据」。提交后形成 `lc-02`（待审）。此处体现的是：**系统的拒绝不是弹个错就完了，而是告诉他最高能到哪、缺什么。**

### 10.5 场景 E：履约未达成触发降级（exp-10 ← fr-04）

UK 项目履约记录 `fr-04`：「延迟交付赔偿 ≤0.5%/周，上限 10%」实际按 1%/周赔付 6%（上限 15%），状态 `missed`，核验日 2026-09-25。

系统按 BR-14 自动生成一条降级申请：`exp-10`（履约保函与 LD 上限需在投标阶段锁定）从 A → C，理由「履约记录 fr-04 显示 LD 条款未按经验推荐的 0.5%/周执行，实际赔付 6%，该经验的可复用性下降」。该条状态被置为「待复核」，列表中显示「变更待审 lc-04」徽标与一行灰字「由履约记录 fr-04 触发」。

知识库管理员点开看到证据直连履约记录，法务陈立（只读）也能在同一抽屉看到这条降级来由——**法务关心的是「我们承诺过什么、兑现了没有」，这条链路在这里闭合。**

### 10.6 场景 F：引用记录（exp-05 → p-01）

新项目 p-01 CZ-Morava 25MW/100MWh 在做对比分析时，工程师李维从 `/match` 引用 exp-05「循环寿命测试条件必须四项齐全」，用于对比分析 `cmp-012` 行（循环寿命，含 DoD/温度/SoH 三个条件列）。

本页「引用记录」子 Tab 显示：

| 引用方项目 | 引用人 | 引用时间 | 用于何处 | 引用时等级 |
| --- | --- | --- | --- | --- |
| p-01 CZ-Morava 25MW/100MWh | 李维 | 2026-10-20 11:42 | 对比分析 · cmp-012 循环寿命行 | A |

三周后该经验若被降级为 B，这条记录仍显示「引用时等级 A」，不回溯篡改（BR-15 的「快照」含义）。

### 10.7 场景 G：缺字段禁止入库（exp 草稿）

复盘刚写入的草稿「消防方案按最高等级配置未被加分」缺「复核日期」与「证据来源页码」。抽屉顶部显示：

> 入库校验 10/12 · 缺：证据来源（页码）· 复核日期

### 12.2 闭合校验

- `/retro` 提到「入库并查看经验」→ 本页有 `?open=` 接收逻辑；
