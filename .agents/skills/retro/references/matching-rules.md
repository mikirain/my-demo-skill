# 相似项目匹配规则（经验"适配"而非"照搬"）

> 加载时机：Step 6（可选分支）用户问"这条经验能不能用到 X 项目"时加载。
> 上游依据：PRD v1.1 §5 匹配公式 + 输出结构。

## 1. 打分公式（与 `scripts/score_match.py` 完全一致）

```
score = 国家匹配(30) + 规模相近(25) + 技术路线(15) + 客户类型(15) + 合同模式(15)   → 0–100
```

| 维度 | 满分 | 得分规则 |
| --- | --- | --- |
| 国家 | 30 | 同国 30；同区域 15（西欧 `DE/UK/IT`、中东欧 `CZ/PL`、大洋洲 `AU`、其他 0） |
| 规模 | 25 | 规模比 0.8–1.2 倍 25；0.5–2 倍 15；0.25–4 倍 5；其余 0 |
| 技术路线 | 15 | `productModel` 相同 15；`route` 相同 10；同技术家族（LFP 之间）6；其余 0 |
| 客户类型 | 15 | 完全相同 15；同大类 8（`开发商/IPP`、`公用事业`、`EPC 总包`、`工商业`） |
| 合同模式 | 15 | 完全相同 15；相近 8（`EPC`↔`供货+运维`、`供货`↔`供货+运维`） |

**匹配度只作排序依据**，不得单独作为"可套用"结论。报告必须同时呈现"可借鉴点"与"差异条件"。

## 2. 输出必须包含的四块

| 输出 | 来源 | 硬要求 |
| --- | --- | --- |
| 匹配度 | 打分公式 | 标 `0–100`，附"不代表可直接套用" |
| 可借鉴点 | `experience.scope` 命中的条件 + 高分维度 | 按等级分区：**A/B 进"可借鉴"区，C 单列"待验证假设"区**（BR-12） |
| 差异条件 | 未命中的维度 | 用具体数值写差异（"规模差 4 倍"而非"规模不同"） |
| 适用边界 | `experience.scope` 原文 | 只允许引用原文，禁止改写成"普遍适用" |

## 3. 分区渲染规则

```
可借鉴（A/B）        → 可以写入投标策略，B 级必须附"限制说明"
待验证假设（C）      → 只允许出现在单独区块，标注"需在本项目验证" + verificationPlan
不可引用（deprecated）→ 不展示，或仅在"历史参考"折叠区注明停用原因
```

## 4. 差异条件撰写规范

差异必须写成"维度 + 数值 + 结论影响"三段：

| 差 | 好 |
| --- | --- |
| "国别不同" | "国别不同（CZ→DE）：并网规范由 EN 50549-1 改为 VDE-AR-N 4110，需重新做并网认证" |
| "规模差得多" | "规模差 3.8 倍（100→230MWh）：单价随规模下降，原 TCO 结构不成立" |
| "客户类型不同" | "客户类型不同（IPP→公用事业）：评标更看重可用率罚则，TCO 权重下降" |

## 5. 引用动作（BR-15）

引用经验到新项目时，必须写 `experiences[].references[]`：`projectId` / `citedBy` / `citedAt` / `usedIn`。
不能只写"已引用"，必须注明用在哪个文件哪一节。被降级（BR-14）后，按 `references[]` 列出受影响项目并提示复核。

## 6. 反模式

| 反模式 | 后果 | 纠正 |
| --- | --- | --- |
| 只看匹配度排名 | 把 85 分当"可以照抄" | 强制看差异条件区 |
| 把 C 级经验塞进可借鉴区 | 未验证假设被当结论 | 分区渲染，脚本按 `evidenceLevel` 分区 |
| 忽略 `scope` 原文 | 经验被滥用 | 适用边界只允许原文引用 |
| 用相邻期项目"条件相似"代替核对 | 国别/规模差异被吞掉 | 逐维度核对并写数值 |
| 引用不写 `usedIn` | 降级时无法定位受影响文件 | BR-15 必填四项 |
