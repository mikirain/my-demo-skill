# 证据分级与规则体系（A/B/C + BR/LR）

> 加载时机：Step 2 判定每条赢因/经验的等级时**必须**加载；Step 4 校验失败时按本文件定位修法。
> 核心立场：**中标 ≠ 标书里每一项设计都导致了中标。**

## 1. 三级定义

| 级别 | 定义 | 典型证据 | 可写入的载体 | 界面形状编码 |
| --- | --- | --- | --- | --- |
| **A 已证实** | 有直接证据指向因果 | 正式评分表分项得分、评标反馈点名优势、客户书面（邮件/纪要）明确认可 | 三栏"已证实优势"、策略建议、`verified` 候选 | 实线 |
| **B 多材料** | 多份材料共同支持，无评标直接证据 | 投标文件 + 澄清记录 + 谈判纪要共同指向；中标公示 + 客户感谢函 | "可能原因"参照区，须注明限制 | 双线 |
| **C 待验证** | 只有结果或只有内部推断 | 中标本身、内部复盘会共识、销售口述 | 仅"待验证假设"区，**禁止**进入结论载体 | 虚线 |

形状编码是硬要求：只靠颜色区分在打印/色弱场景失效。

## 2. 判定决策树（逐条走，不跳步）

```
Q1 这条结论有"直接指向因果"的书面证据吗？（评分表分项 / 评标反馈点名 / 客户书面认可具体设计）
   有 → 候选 A，进 Q2 复核
   没有 → Q3

Q2 该证据是否来自正式评分表或评标反馈原文？且能定位到页码/条目？
   是 → A（仍需人工确认；无评分表项目直接否定，见 BR-13）
   否（是客户邮件/纪要认可） → A，但必须写清"客户认可的具体表述"+ 时间 + 出处

Q3 有多份材料（≥2 份、独立来源）共同指向同一因果吗？
   有 → B
   没有 → C

Q4 只有"结果"（中标）或只有"我方自述"吗？
   是 → C；若该判断影响后续投标策略 → C + verificationPlan（在哪个项目/何时验证）
```

**自检三问**（每条结论都问）：
1. 如果竞对也中标了，这条还成立吗？——不成立说明它是入场条件，不是赢因。
2. 这条证据是"客户说的"还是"我们说的"？——"我们说的"最高 B。
3. 证据的物理文件在哪里？——找不到文件即 C。

## 3. 无正式评分表项目的替代证据标准（B 级组合）

海外项目评标反馈获取率天然偏低，`hasScoreSheet=false` 时按 BR-13 最高 B。以下组合**可**构成 B：

| 组合 | 能否 B | 说明 |
| --- | --- | --- |
| 客户书面澄清/纪要明确接受某偏差 + 中标公示 | ✅ B | 两个独立来源，指向同一技术判断 |
| 客户感谢函/复购邀约点名某能力 | ✅ B | 客户侧文件，但非评审结论 |
| 合同签署 + 履约达成 | ⚠️ 仅结果证据 | 只能支持"做得到"，不能支持"因此中标" |
| 我方投标文件自述 + 销售口述 | ❌ | 单一来源且为自我陈述 → C |
| 竞对参数缺失但"我们更强"的内部结论 | ❌ | 不可比 + 内部推断 → C |

**禁止**：用上述组合包装成 A；用"客户没反对"记为接受。

## 4. 硬规则（BR，脚本可机械检查）

| 编号 | 规则 | 检查点 | `validate_retro.py` |
| --- | --- | --- | --- |
| **BR-11** | 无来源不入库：经验必须有 `evidenceLevel` + 非空 `evidenceSources`，且每个来源能在 `evidence[]` 池中定位 | `evidenceSources[]` 全为已存在 `EV-*` | ERROR |
| **BR-12** | C 级不进结论载体：C 级 `conclusionCarrier` 必须为 `false`；C 级经验必须 `state=draft` 且填 `verificationPlan`；匹配结果中 C 只进"待验证假设"区 | 字段级 | ERROR |
| **BR-13** | 无评分表最高 B：`case.hasScoreSheet=false` 时，任何 `winFactors[].level` / `experiences[].evidenceLevel` 不得为 A | 全量扫描 | ERROR |
| **BR-14** | 履约 `missed` 自动降级：关联经验不得保持 A，必须有 `pendingChange`（to B 或 C），`note` ≥ 6 字，并写入 `changeHistory` | 通过 `fulfilment[].experienceIds[]` 反查 | ERROR |
| **BR-15** | 引用留痕：经验被引用到新项目时 `references[]` 必须含 `projectId`/`citedBy`/`citedAt`/`usedIn`；被降级后需向引用方提示 | `references[]` 字段完整 | ERROR（缺字段）/ 报告告警区 |

## 5. 等级变更审批（LR，v1.1.1）

| 编号 | 规则 | 脚本检查 |
| --- | --- | --- |
| LR-01 | 升级必须新增证据：`to` 高于 `from` 时 `newEvidenceIds` ≥ 1 条且指向池内真实证据 | ERROR |
| LR-02 | 升 A 必须有直接证据且来源项目有正式评分表（否则 BR-13 拒绝） | ERROR |
| LR-03 | 变更必填理由 ≥ 6 字，写入审计 | ERROR |
| LR-04 | 双人规则：`approver ≠ requester` | ERROR |
| LR-05 | 单条经验同时只允许一个待审变更（`status=pending` 计数 ≤ 1） | ERROR |
| LR-06 | 通过后追加证据来源并置 `verified`，去重合并；`deprecated` 条目不改状态 | 报告提示 |
| LR-07 | 降级可不附证据，但必须写明原因，同样走审批（保守优先） | ERROR（缺理由） |
| LR-08 | 全部变更进 `changeHistory`（发起人/时间/理由/证据/审批人/意见） | WARN |

状态流：`无申请 → 待审批 → (通过：等级生效 + 证据并入) / (驳回：等级不变，原因留痕)`

## 6. 履约降级流程（`missed` 的标准动作）

1. 在 `fulfilment[]` 记录 `status: "missed"`，`note` 写**具体偏差事实**（≥ 6 字，例："本地备件仓未按承诺在 Q2 建成"）。
2. 通过 `experienceIds[]` 找到受益经验；若该经验 `evidenceLevel = A`，必须**立即降级并生效**（BR-14 是自动降级，不是"待批"）：
   - `evidenceLevel` 直接改为目标等级（B 或 C）；
   - 用 `changeHistory` 追加一条 `status=approved` 的 A→B/C 记录，`requester` 写"系统自动触发（<FU 编号> missed，BR-14）"，`approver` 写人工复核人（LR-04 要求二者不同）。
   - **不要**用 `pendingChange` 表达这次降级：`pendingChange` 表示"尚未生效的申请"，其 `from` 必须等于当前等级；把已生效的降级写成 pending 会与 BR-14 冲突（`validate_retro.py` 报 `[STATE]`）。
3. 降级目标：A → B（仍有其他材料支持）或 A → C（只有结果）；`reason` 写清履约事实与推断断裂点。
4. 检查 `references[]`：列出被影响的项目，在报告"引用影响面"区逐条列出（BR-15）。
5. 审批走 LR（双人规则）；通过后 `state` 回归 `draft`-需复核，`changeHistory` 追加记录。

## 7. 人机边界（红线编号 BR-16~20，不可让渡）

| 编号 | 红线 | AI / 脚本 可以做 | 必须人做 |
| --- | --- | --- | --- |
| **BR-16** | 不产出报价、不推断对手利润率/成本结构 | 记录报价**结构占比**与 TCO 影响 | 定价决策、成本核算 |
| **BR-17** | 不产出对外承诺 | 摘录投标文件/谈判纪要中的既有承诺原文 | 承诺口径确认与合同签署 |
| **BR-18** | 不自动定级、不自动入库 | 依决策树给**建议**等级并标"待人工确认"；生成 `state=draft` 草稿 | 等级确认、`draft → verified`、`deprecated` |
| **BR-19** | 缺数据标 `pending`，禁止编造 | 记录缺口并写入 `openItems` | 补数据、决定是否带缺口复盘 |
| **BR-20** | 引用与交付留痕 | 机械执行 BR/LR 拦截并给字段级报错；匹配打分与解释 | 引用确认、报告签发、对外脱敏 |

其他机械保障（脚本可查）：BR-11~15 与 LR-01~05 见 §4、§5；BR-16/18/19 由 `validate_retro.py` 部分拦截（`noQuoteStatement`、`state=verified`、空字段），其余靠流程。

## 8. 常见"拔高"手法与识别

| 手法 | 表现 | 识别 |
| --- | --- | --- |
| 结果倒推 | "中标了，所以这套配置赢了" | 问"竞对同配置也投了，为什么不是它" |
| 单一来源升格 | 只有投标文件自述却标 A | 查 `evidence[]` 里是否存在客户侧文件 |
| 口头认可当书面 | "客户会上说不错" | 无纪要/邮件 → 最高 C |
| 总分冒充分项 | 用总分优势覆盖所有分项 | 逐条对应评分因素表 |
| 参数跨口径比较 | 循环次数 vs 实测容量保持率 | 查可比性（口径/边界/条件） |
